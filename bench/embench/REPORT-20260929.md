# Amu native compiler: Embench-IoT qualification, 2026-09-29

## Result

The standalone ARM64 Amu compiler checked and compiled all 19 named
Embench-IoT ports, and every generated AArch64 correctness export returned
`1`. The compiler ran with an empty `PATH`; Node.js, Java, Clojure and external
compilers were unavailable. Its Mach-O dependencies contain only Apple system
frameworks, `libSystem`, `libobjc`, and `libz`.

This is **not an official Embench score**. Nine ports translate the full
correctness calculation for one benchmark iteration. Ten are smaller
algorithmic probes derived from the named workload. Their numbers demonstrate
native compiler coverage and expose optimization work; they cannot be compared
with published Embench speed or size scores.

## What the result establishes

1. Amu's compiler executable is independent of JavaScript/Node.js and the JVM
   at runtime.
2. The native frontend, verifier, GMIR pipeline, AArch64 backend, KEXE writer,
   native extractor, vector runtime and string runtime process all 19 ports.
3. Nine translated workloads pass their upstream-derived complete correctness
   gates for one iteration, including all XGBoost trees/samples and all
   depthwise-convolution output values.
4. The adapted ports identify the remaining work required before publishing an
   official or whole-suite-equivalent result: full bodies for edn, huffbench,
   nettle-aes, nsichneu, picojpeg, qrduino, sglib-combined, slre, statemate and
   WikiSort's exact algorithm, followed by upstream harness/scale parity.
