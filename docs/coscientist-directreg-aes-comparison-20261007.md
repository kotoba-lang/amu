# AESの直接レジスタ候補：性能改善は認定できず（2026-10-07）

Apple M4（zebulun、Mac16,10）で、既に検証したAES復号候補と、4箇所で各7命令を削減した直接レジスタ候補を、同じ入力・C成果物・実行器で比較した。今回の同時基準との差は0.65%で、事前の改善基準を満たさなかった。命令削減を性能改善として採用しない。C以上の性能という目標も未達。

処理本体1回あたりの平均±標本標準偏差、各構成30試料。

| 同一C成果物 | 1.47329 ± 0.02401 |

基準/候補は1.006563、候補/Cは5.323701。平均差51.48 nsは両標準偏差の和258.05 nsより小さく、速度比も事前の1.05に届かない。改善・悪化・C超えの採択はすべて0件。前のキャンペーンの値と混ぜず、この同時比較だけで判定した。

## 実験と再検査

事前条件は30組採用、最大90試行、各構成最大5回の校正、目標300 ms・最短50 ms。3構成の実行順を回転させ、組全体で負荷4以下、推定バックグラウンドidle 90%以上を要求した。相対標準偏差10%以下、速度比1.05以上、平均差が両標準偏差の和を超える場合だけ改善・悪化・C超えを採択する。

1回だけのキャンペーンで54組を試行し、30組採用・24組除外。校正7回を含め169実行の引数・結果・燃料・CPU状態・採否を保存し、独立担当が全件と統計を再計算した。再キャンペーン・過去の統計の混入はない。測定前には新しい実行器1件のビルドと、基準・候補・Cの計3件の機能検査を通した。いずれも入力32・結果1、ネイティブの燃料消費427,363、Cは0だった。

候補はAmu自身による4世代の自己再ビルドでバイト一致した実験用コンパイラ `4f2c1e1a…` の生成物。AESは40,232 Bから40,120 Bへ縮小し、他18入力の出力は基準とバイト一致する。ただし今回の速度測定はAESだけで、全19入力の新しい性能結果ではない。[実装と566件の有限実行検証](coscientist-directreg-20261007.md)は別の保存証拠として扱う。

最初の測定準備版にあった `compilerMQualificationAccepted` は検証範囲より広い承認名だったため、実行前に別版を作り、通常の生成結果と有限実行検証の受理へ限定した。元の準備版と修正記録を保持した。新候補のコンパイラ全メモリ状態・容量不足・生成後半の拒否・巻き戻しは未保証で、以前の別候補の検査を流用して保証した扱いにはしない。

これは公式Embenchスコアではない。元C成果物のコンパイラと全フラグは不明のまま扱い、製品の既定設定への採用も行っていない。[3ファイルだけで再検査できる保存証拠](evidence/coscientist-inverse-aes-20261007/directreg-negative-timing/README.md)を用意し、親担当も全169実行・3機能検査を再計算した。
