# V8 shape memo：型付き vector の native 制御試験

Amu 製の V8 ネイティブコンパイラで隔離した検査プログラムを作り、固定した3ケースを実行した。ビルド・抽出・通常版の採取を含む7回はすべて正常終了した。独立した二人の実測ログ監査も PASS。性能測定と Embench 本体の実行は0件である。

実際の lx/rd/nm/ck/lw が生成した5関数・4本の OP-CALL を使った。長さ4の vector-alloc から private 関数への寄与4、export 関数の未知長からの寄与0、実際の自己呼び出しで同じパラメーターを保つ場合の neutral -1 を確認した。手作業で構築した SIR の結果ではない。

再生試験は全5関数について、callee の集計をすべて -1 に戻した別々の状態から直接解析とキャッシュ再生を比較した。4本の辺それぞれの4要素、集計された長さ、support、refusal が一致した。すでに集計済みの状態へ再生するだけの検査ではない。自己呼び出しの4要素はすべて -1、未知長の辺は0、割り当て長の辺は4だった。

作業上限に達したケースは query・capture・replay を開始せず拒否した。全3ケースで M の8,388,608セル、領域内 G の147,554語が元の状態と一致し、所有する50,689語がゼロに戻った。任意の M、外部 arena、一般的な定理を検証した結果ではない。

新しい型付き fixture の通常版も採取した。624 B、SHA-256 `c51adf3c8ed7c62c3479e42c9eca2592a763dd1aea15c19998a52c5e77716e5c`、bench の位置424・arity1。KSEED の全 payload と抽出コードは一致した。新しい fixture なので以前の成果物との一致や、通常版を実行した結果は主張しない。

この試験のコンパイラの4世代自己再ビルドは [V8 の別証拠](coscientist-vector-typed-v8-20261007.md) に帰属する。この試験が4世代のビルドを再実行したとは数えない。[scalar の21ケース](coscientist-vector-shape-memo-controls-20261007.md)で残した正値・未知長・自己呼び出しの未検査部分を、今回の固定した型付き fixture の範囲で補った。

製品ソースと emitter は変更していない。実際に生成時の検査を省いた箇所は0。次は証明情報の生成中の保持と、局所的な vector-at の範囲検査の省略を、既定で無効の実験として設計する。C以上の性能、公式 Embench スコア、製品100% selfhost は未達成である。
