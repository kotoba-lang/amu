# Native private length clones: verified, rejected for performance

The [constructor/context diagnostic](coscientist-length-context-20261006.md) is now used by an **actual native Kotoba compiler candidate**, rather than merely a census. It creates private function/length versions and lowers proved literal-index accesses without the original unsigned bounds sequence. The current593 fixtures/25,658 native expectations, three-generation fixed point, original19 result/fuel and209 full supervisor groups pass. Independent complete SIR/context/metadata and actual machine translation audits pass, together with304 focused constructor/entry pairs,161 resource boundary pairs and actual compiler mutants. **One fresh quiet-host campaign finds no qualified improvement and a40.36% statemate regression. The candidate is rejected and not promoted; C-or-better remains unachieved.**

## Actual candidate contract

This one-off excluded native algorithm operates on checked, valid typed SIR. It retains the earlier bounded closed-operation and normal-return identity analysis. Each generic context starts with unknown arguments; private contexts are seeded only by an actual constructed length at an admitted direct call. Final CFG facts, not transient facts, populate a bounded sparse table. Context keys include both function and exact length. Allocation lengths outside0..4096, unknown/effectful/indirect/alias-changing paths, invalid labels and failed analyses retain the original route.

Successful private contexts append deterministic FN/SIR/label blocks. All16 FN fields are copied except native code/start, private kind, export/symbol/node fields: code0, copied start, FK-PRIV, export0, symbol0 and node0. This is internal native representation; the source/checked semantic definition and its DefCID authority are unchanged. Original metadata, public export flags and all public access guard flags remain unchanged. Calls are redirected only with an independently proved exact length; all private calls/branches/labels are remapped to their actual versions. No FADDR or indirect call is redirected.

Only private source sites with a proved nonnegative literal below the exact vector length receive a guard-map flag. The known access emitter retains original index materialization, handle validation, register/protection/context contract, data operation, fuel and publication. Mode0 removes the CMP/LO/UDF bounds portion of vidx, retaining descriptor/items loads. Mode2 retains the existing original positive-witness descriptor cache and private tail ABI, then omits the bounds portion. Mode1 reads conservatively retain their original path. **732 source guard-map sites do not establish732 emitted removals**: fused/skipped/other-mode sites require actual machine validation.

The prepass is disabled for replaceable-import/open generation. Before any new generation on an already transformed M, an owned persistent heap record restores original public CALL operands and original FN/SIR/label counts. The expanded G record has explicit origin/magic fields outside the per-function reset, with bounds validation; source/FF-node fields are not repurposed for undo. Capacity is preflighted before source edits. Failure/no clones returns the generic source. A function-relative fact buffer is reused across contexts rather than retaining a full-program table. This bounds both work and unnecessary allocation.

Private versions are reachable through the proved direct edges. Public definitions/exports and original function-address expressions retain their generic entry. The contract assumes the existing checked-SIR/runtime table authority; it is not a CFI proof against a privileged host invoking an arbitrary raw native offset or modifying owned compiler memory. Neither runtime result caching nor capability/authorizer memoization is introduced. Optimizer/source/compiler/target/internal-ABI recipe and resulting artifact hashes are separate from semantic DefCID.

## Failures caught and corrected without changing expectations

V0 was an authoring build that still printed diagnostic collector output; output calls were removed before qualification. V1 passed the original19/fixed-point checks but its fixture generator exhausted the existing vector-item ceiling: used134,217,688 of134,217,728, then SIGILL. V2 replaces the full-program fact table with a longest-admitted-function buffer; no supervisor ceiling changes. It gets below the limit but the original `clamp_closed` guard becomes0 after `gn-run-open` regenerates transformed M. V3 records/restores original edges/counts and passes that same guard plus every original native expectation. Those earlier versions are retained and unqualified.

The excluded frozen fixture harness initially lacked its current helper module; the exact helper was copied, not recreated. Observer hooks initially missed a moved clause/no-clone return; explicit pre/post hooks and full-field observation were added and all19 rechecked. The independent oracle initially shadowed its final function-count variable; it now uses original count plus independently selected versions. Native source/semantic expectations were not adjusted to fit that oracle error.

## Performance gate

The [registered verification](evidence/coscientist-private-length-clones-20261006/next-verification.json) was completed above before timing. A sealed candidate package pins those native proofs, three generations, exact original sources, product/candidate binaries and the unchanged timing specification. A fresh zebulun M4 campaign measured the five changed original workloads with rotating product/candidate/C triples. Fourteen unchanged images are independently byte-identical; they are not presented as newly measured results.

The campaign retains rejected triples and requires30 accepted triples, maximum load4, estimated background idle≥90%, relative SD≤10%, speedup≥1.05 and mean difference greater than the sum of SDs. This is the existing aligned native comparison protocol, not an official Embench score. No repeated unchanged timing, benchmark-name admission, smaller workload, relaxed golden or static-count speed estimate is used here. Product files, `bin/amu`, current golden and workload sources remain unchanged. This new excluded optimizer and independent schemas are a documented one-off research authoring exception, not mechanical product refactoring.
