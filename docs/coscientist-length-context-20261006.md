# Actual constructor length facts reach private analysis contexts

Following the [normal-return identity summaries](coscientist-shape-summary-20261006.md), a new Kotoba diagnostic propagates actual constructed vector lengths and literal indices through CFGs and direct closed calls. Its native output agrees with an independent tuple oracle on all19 pinned original workloads, and all19 generated target bytes/offsets remain exactly the product's. **No native bounds check has yet been removed, no speed was measured, and C-or-better remains unachieved.**

## Concrete semantics and admission

Each of16 local and16 temporary slots holds unknown, an exact scalar literal, or an exact vector length. The vector fact is established only on the normal successor of actual `RT-VECTOR-ALLOC` with a proved nonnegative literal length at most4096, or actual VEC/VECP with an admitted literal size. Existing allocation/fuel/failure order remains untouched. It is a static fact conditional on execution returning from that operation, not a claim that every constructor executes or succeeds.

Copies move facts. Branches intersect equal facts; unequal values/types erase them. Integer/comparison/unary outputs lose scalar literal facts conservatively. Admitted element reads/counts/stores use their existing contracts; the in-place result preserves the actual input vector length. A closed direct callee preserves facts about existing locals, and its result preserves its first argument only if the earlier normal-return identity proof applies. Unknown/effectful/indirect calls erase all facts. A fresh admitted allocation can preserve existing local vector lengths, but this does not preserve a cached native base pointer across table reallocation.

Every function initially has a **generic context** with unknown parameters. After its bounded CFG reaches a fixed point, reachable callsites with an exact first-vector-argument length can add a separate `(callee, length)` context, provided the callee has an admitted closed-operation summary. Other parameters remain unknown. Return identity is used only to propagate the caller's result; it is not required to analyze a closed scalar-returning callee's known vector argument. Thus verify-bits can receive a length context without claiming that its scalar result is the vector.

Context dedup includes both function and exact length, including zero. Distinct constructed lengths never become a universal property of a function or its public entry. Within a context, each CFG uses rooted transfers and a deduplicated worklist. Only final incoming facts are emitted or used to seed downstream contexts; transient optimistic states cannot create a private path. Duplicate/missing/foreign labels and reachable END refuse the context. Per-function bounds,128-times-body CFG work and4096 total contexts bound the diagnostic; failed global work invalidates its result. Unknown/large dimensions are reported as skipped. None of this writes compiler M/G.

For RT vector-at/assoc! and the existing exact direct wrappers, the report records the actual site, context length, vector length and literal index. It records out-of-range constants too: only `0 <= index < exact length` is a prospective bounds-removal candidate. Handle validation, fuel/traps/resource/partial-write observations remain separate obligations. A length fact can survive a merge of two different handles with the same constructed length; it does **not** establish handle identity or justify omitting handle checks.
