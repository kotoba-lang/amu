# ADR 0364 — The native vector table maximum: 4 Mi → 64 Mi handles

- Date: 2026-10-03
- Status: Accepted (agent MEM2, under the owner's wave instruction "raise the loader vector table limit by ADR via the
  limits authority (vector table 4 Mi -> 64 Mi)"; reversible: reverting restores constant 15 and regenerates).
- Amends: amu `tools/kexe_loader_decisions.kotoba` constant 15 (`:profile/native :cells` vector table address-space
  maximum, 4 194 304 -> 67 108 864) and so `KEXE_VECTOR_MAX` in the generated region of `tools/kexe_loader.c`
  (regenerated by `scripts/gen-loader-decisions.cljk`, both ISAs' decision code); adds `:profile/native :cells
  :vector-table-max` to the vendored `resources/kotoba/lang/limits.edn` and `kotoba.compiler.limits/table` (the
  upstream kotoba-lang `lang/limits.edn` needs the same line: filed in seed/CONTRACT-REQUESTS.md).
- Related: ADR 0361 (growth regions), 0362 (the process followed here), docs/selfhost-analyze-memory-20261003.md
  (the measurement), docs/selfhost-coscientist.md H-M3 / H-M4.

## Context

The vector table is the loader's second cell pool: one 16-byte entry (offset, length) per vector handle, in the
shared mapping; the item words live in a separate arena (`KEXE_VECTOR_ITEM_MAX`, 128 Mi words). Every `conj`,
`vector-alloc`, `assoc`, slice and empty vector mints a handle, and a handle is never reused within a run. The per-run
budget (`KEXE_VECTORS`, default 4 096) is what a program gets; constant 15 is the ceiling a budget may name and the
size of the array.

The frontend's `analyze` pass, run natively (the whole linked frontend compiled by the seed backend, FRONT 2026-10-03),
mints ~150-200 vector handles per byte of real source. With the 4 Mi ceiling one process held about 28 KB of the
seed's own sources: the seed MANIFEST prefix 00-ns..01-mem (28.7 KB) traps `:vector-table-exhausted` with hash-consing
on and off; 4 Mi was the measured wall.

## Decision

Constant 15 = 67 108 864 (64 Mi). Nothing else moves: the default budget stays 4 096, the pair arena stays 64 Mi,
the item arena stays 128 Mi words, and no ABI offset changes (the table is inside `struct kexe_shared_v11`, after
`string_pool` and before `vector_item_used`; guests reach it only through the context pointers `vectors_base` /
`vector_used_pointer`, whose offsets 312/320 are asserted and unchanged).

## Cost

| what | per handle | at 4 Mi | at 64 Mi | touched |
|---|---|---|---|---|
| shared table entry | 16 B | 64 MiB | 1 GiB | only when minted (MAP_ANONYMOUS, never memset) |
| growth-region tag (`kexe_vector_region`, private) | 4 B | 16 MiB | 256 MiB | only when minted |
| growth-region slots (private) | 16 B per region | 64 MiB | 1 GiB | only when a region is made |

Address space per loader process grows by ~2.2 GiB (from ~3.3 GiB); resident memory does not: a 783-byte analyze
case peaks at 26.07 MB RSS on the old loader and 26.08 MB on the new one (3 runs each, same guest and budgets). Handles
stay below 2^32, so the 32-bit handle in a hash-consing entry and the 32-bit region index are unaffected.

## Verification (measured 2026-10-03, host load 80-270, so timings are not results)

- `gen-loader-decisions.cljk --check`: region up to date. `test-loader-decisions.cljk`: the 16 black-box loader cases
  that differ from the C-decisions loader (0d244a95) are exactly the `KEXE_VECTORS` budgets 4 194 305 .. 67 108 864
  (now admitted) and the ceiling number in the refusal text above it; the one other differing case (`KEXE_FUEL=2`,
  SIGALRM) is the 3-second default wall under load 80+, unrelated. The 10 unclassified functions it reported (the
  census added here, and the earlier hash-consing and string-region helpers) are now classified.
- The analyze guest's 263 recorded programs answer byte-identically on the old and the new loader (hash-consing on and
  off). A program needing more than 4 Mi handles answers correctly above the old ceiling: the seed prefix 00-ns..01-mem
  (5.37 M handles) gives exactly the host's HIR (`form/eq` OK); 00-ns..02-io and ..10-lex (7.9 M / 13.5 M handles)
  equal the host's HIR modulo one known guest difference (duplicates in the `:named-operations` set).
- Seed gates G1 and G5 at r6b on a clean worktree: see seed/rungs or the commit message of this change.

## Consequences

The next wall of `analyze` in one process is the pair arena (64 Mi) at roughly 220-290 KB of source with hash-consing
(docs/selfhost-analyze-memory-20261003.md); raising it is the same kind of decision and is not taken here, because the
measured cause of the volume (constant tables re-materialised per call in the frontend) is cheaper to remove.
