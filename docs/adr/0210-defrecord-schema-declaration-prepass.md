# ADR 0210: defrecord schema declaration prepass

Status: accepted

## Context

ADR 0209 made an exact namespace schema entry compatible with the descriptor
generated by a later `defrecord`. It made recursive variants possible, but
required authors to repeat the complete record descriptor once. The compiler
already collects eligible top-level `defrecord` descriptors before expression
analysis; the namespace parser nevertheless validated the authored `:schemas`
map before those generated entries were merged.

## Decision

Keep the namespace schema map raw after its bounded clause-shape checks. Merge
the eligible same-module `defrecord` descriptors collected by declaration
expansion, check exact same-name collisions, and validate the resulting closed
schema graph once before constants, signatures, or expressions are analyzed.

An authored exact forward declaration remains accepted for compatibility. An
incompatible declaration still fails with
`:kotoba.error/record-schema-collision`. A reference to an undeclared name, or
to a record descriptor that is ineligible for the closed graph, still fails as
an undeclared schema reference.

## Consequences

A recursive namespace may write only the meaningful edge:

```clojure
(ns example
  (:schemas {:example/Node
             [:variant :example/Node
              [[:entry [:ref :example/Entry]]]]}))

(defrecord Entry [k :string v :string])
```

The compiler remains closed-world and declaration-bounded, but authors no
longer repeat a descriptor that `defrecord` already defines. No ambient lookup,
runtime type discovery, or validation deferral beyond frontend analysis is
introduced.

## Evidence

`record-protocol-static-dispatch-test` compiles and executes a variant that
refers to a later record without an explicit forward descriptor, retains the
exact-declaration compatibility case, and proves incompatible collisions still
fail closed.
