# ADR 0209: exact defrecord schema forward declarations

Status: accepted

## Context

Namespace schema tables are closed and validated before declarations are
expanded. A recursive variant can therefore refer to another entry in the same
table, but could not refer to the nominal schema generated by a later
`defrecord`. Repeating that record descriptor in `:schemas` was then rejected
as a collision, making a safe recursive variant containing a nominal record
impossible to author with `defrecord` syntax.

## Decision

Permit a namespace `:schemas` entry and a generated `defrecord` schema to share
one identity only when their complete descriptors are equal. Treat the
namespace entry as an exact forward declaration. Reject the same identity with
different field names, order, count, or types using the existing
`:kotoba.error/record-schema-collision` category.

## Consequences

Recursive variants may name a later nominal record without weakening the
closed schema graph or nominal identity. The declaration is intentionally
explicit because the namespace table must validate before the record form is
expanded. Exact equality prevents shadowing, structural substitution, and
schema drift.

## Evidence

`record-protocol-static-dispatch-test` constructs, matches, and projects an
exact-forward-declared record inside a variant on KIR, and proves that an
incompatible same-name declaration remains fail-closed.
