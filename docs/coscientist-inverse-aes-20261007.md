# AES復号の実験状況（2026-10-07）

燃料更新最適化の実験用コンパイラを基準に、閉じたAESテーブル計算を `AESD`・`AESIMC` に置き換える復号経路を追加した。同条件の測定でAESの改善を確認したが、C超えは未達。製品採用は未実施。通常設定では無効で、私有の実験設定でのみ有効にする。

## 確認できたこと

- 元の4つの復号テーブルと、バイト配置・逆変換・完全な64ビット鍵のXORを結び付けた値保存の証拠を検査した。最初の直接SMT問い合わせで得た2件の `UNKNOWN` も保持し、後の分解した証明と区別している。
- 最初の実装はコード領域の予約条件が不足して独立検査に失敗した。その実装と失敗記録を保持し、予約条件を追加した第2版を別の候補として検査した。
- Amuが生成した第2版のコンパイラは4世代でバイト一致した。879,496 B、SHA-256 `7ea1b815396ef85dabe25a5c648efe74ff853d823507412c59178c1e26795f92`。この一致だけで製品全体のセルフホスト完了を意味するものではない。
- 元19本のイメージを生成した。有効時の変更は `nettle-aes` の4箇所のみで、他18本は基準とバイト一致。無効時は19本すべてが基準とバイト一致した。
- 4箇所の引数捕捉、共有する燃料更新コード、分岐、残りのコード、再配置、テーブルを比較した。各対象箇所は65語から73語になり、合計32語増えた。故意に壊した8種類の命令を独立検査が拒否した。
- 専用命令単体をローカルのMacBookPro18,4で実行した。固定1,108入力すべてが元の復号テーブル計算と一致し、3種類の誤実装は事前指定した入力で検出できた。4ビルド・16実行の記録を保持した。
- Amu自身で生成した診断用4経路を、12入力と14種類の燃料量で比較した。168組・336実行で、元の計算式、終了状態、燃料残量、報告される使用量が一致した。成功時の消費は入口1回＋内部6回。燃料7は残量0で正常終了する。
- 保存レジスタx19〜28とスタック/LRの28件、元のローダーとの64ビット結果比較4件、固定した8種類の誤実装の検出も通った。合計376実行・23ホストビルドを再試行なしで保持し、独立担当と親担当が保存結果を再検査した。保持する鍵の物理レジスタは生成記録に基づきx19と確認した。

## 検証の経過

有限範囲の容量・エラー・状態再利用と元19本の機能検証を終えた。同じM4ホストで固定したCイメージとの性能比較へ進む。

容量検査用コードは最初の基準側入力で失敗した。第1版ではローダーのコマンド設定が表示を抑え、終了コード69だけが得られた。同じ入力1件の別途の原因観測で戻り値12101を確認した。型推論の再処理を追加した第2版も、同じ入力で12101を返した。各版とも最初の失敗で停止し、逆側と残りのケースは実行していない。両版の[失敗証拠](evidence/coscientist-inverse-aes-20261007/compilerM-failures/fixture-v1/README.md)と[第2版の補足](evidence/coscientist-inverse-aes-20261007/compilerM-failures/fixture-v2/README.md)は、別の場所で保存結果を再検査できた。

さらに、フロントエンドの状態を直接返す[診断1件](evidence/coscientist-inverse-aes-20261007/compilerM-failures/localization/README.md)で、エラー2101・ソース位置32579（80行目の `rem`）を観測した。通常のCLIは元ソースに `ck-r6b-lib` の標準関数定義を追加するが、検査用コードはその処理を省いていた。

通常CLIと同じ入力準備に直した[第3版の保存結果](evidence/coscientist-inverse-aes-20261007/compilerM-failures/fixture-v3/README.md)では、30呼び出し中29件が通った。両版のケース0〜13と基準側のケース14が通り、復号候補のケース14が9008を返して停止した。ケース15（状態再利用）は未実行。ケース3・5は最適化の入場条件だけを検査し、ケース14は故意に不正な内部状態を作る診断である。ケース14には、レジスタ番号40に対してエラーを期待する条件があったが、既存エンコーダーは下位5ビットの8として扱うため、その期待は誤っていた。複数条件をまとめた9008だけで他の条件の値は確定しない。失敗を保持し、個々の値を観測してから期待値の修正を独立レビューする。容量・エラー・再利用検査の全通過や、候補実装の不具合が確定したという結果ではない。

その後の[個別観測と第4版の3件](evidence/coscientist-inverse-aes-20261007/compilerM-failures/fixture-v4/README.md)では、正常生成時に使用量73語・適用回数1回が増えることを確認した。独立レビューした期待値修正では、その正しい更新を参照結果にも反映し、8,388,608セルの完全一致を要求した。修正した復号側のケース14と、両構成のケース15が通った。第3版の29件と第4版の3件で32種類のケース・構成を確認したが、単一版の32件キャンペーンとは扱わない。生成後半のエンコーダー拒否は未検証で、ケース15の一致範囲は使用中のコード・再配置・関数・IR・リテラル領域に限る。この有限範囲を満たしたとして、元19本の機能検証へ進んだ。

[元19本の機能検証](evidence/coscientist-inverse-aes-20261007/local-functional/README.md)は、99組198実行で結果・終了状態・燃料・報告使用量が一致した。最初の反復1回19組を実行後、追加実行前に反復0回の期待値が1と記録されている誤りを見つけ、全19本のソースから0が正しいと確認した。元の計画を保持し、期待値を訂正した別手順で残り80組だけを実行した。38の診断用ホストビルドを再利用し、最初の38実行は繰り返していない。内訳はゼロ回の境界19組、正の反復回数38組（1回と32回、depthconvのみ多回数を2000回）、AESの燃料境界42組。AESの32回は正常終了し、燃料消費427,363が基準と一致した。ゼロ回の境界検査を処理本体や性能の証拠にはしない。独立担当も99組の生ログを検査し、測定ホストでの57件の機能確認へ進めると判定した。この機能検証自体は性能や製品採用の証拠ではない。

[遠隔機能検証の証拠](evidence/coscientist-inverse-aes-20261007/remote-functional/README.md)では、Tailscaleのzebulun（Mac16,10、Apple M4）に封印済み入力を転送し、19の実行ホストを構築した。新しい機能確認57件（19本×基準・復号候補・C）は、結果1・終了コード0・期待した燃料消費で全件一致した。arm64・AES・CRC32の実機機能と全入力・実行ファイル・生ログのハッシュを独立検証した。これは機能確認であり、診断の経過時間を性能値には使わない。その後、固定条件による一度の性能測定を終え、[比較表](coscientist-inverse-aes-comparison-20261007.md)に結果を記録した。

現在の呼び出し検証は有限入力と報告される最終状態を対象とする。動的モードの経路では第4状態値を-1に固定し、固定モードの経路では状態値と鍵を変えている。未報告のメモリ内容、非同期の更新途中、ABI全体を網羅した保証にはしない。

今回の復号候補の[新しい性能比較](coscientist-inverse-aes-comparison-20261007.md)では、AESは1.8453倍高速化（45.8090%短縮）した。候補はCの5.4905倍の時間で、C超えは未達。他18本に採択する改善・悪化はなく、全19本の候補/Cの記述的幾何平均は7.039733だった。前段の燃料更新候補の[測定結果](coscientist-resident-fuel-comparison-20261007.md)では、AESの時間は8.7483%短縮したが、Cの約9.9885倍だった。19本の候補/Cの幾何平均は7.249833で、全体の改善は確認できていない。これらは公式Embenchスコアではない。

## 証拠の範囲

値保存、生成コードの検査、専用命令単体の実行、呼び出しの実行、性能を別々に判定する。内容のハッシュと、実験設定・使用したコンパイラ・実行ホストの記録を分ける。規則が適用されたことやコンパイラが固定点になったことを、性能向上の証拠にはしない。

[保存済み証拠とオフライン再検査手順](evidence/coscientist-inverse-aes-20261007/README.md)を公開用にまとめた。過去の失敗と未検証範囲を保持し、親担当も3ファイルだけの新しいディレクトリで再検査した。
