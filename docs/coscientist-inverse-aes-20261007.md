# AES復号の実験状況（2026-10-07）

燃料更新最適化の実験用コンパイラを基準に、閉じたAESテーブル計算を `AESD`・`AESIMC` に置き換える復号経路を追加した。製品採用と性能判定は未実施。通常設定では無効で、私有の実験設定でのみ有効にする。

## 確認できたこと

- 元の4つの復号テーブルと、バイト配置・逆変換・完全な64ビット鍵のXORを結び付けた値保存の証拠を検査した。最初の直接SMT問い合わせで得た2件の `UNKNOWN` も保持し、後の分解した証明と区別している。
- 最初の実装はコード領域の予約条件が不足して独立検査に失敗した。その実装と失敗記録を保持し、予約条件を追加した第2版を別の候補として検査した。
- Amuが生成した第2版のコンパイラは4世代でバイト一致した。879,496 B、SHA-256 `7ea1b815396ef85dabe25a5c648efe74ff853d823507412c59178c1e26795f92`。この一致だけで製品全体のセルフホスト完了を意味するものではない。
- 元19本のイメージを生成した。有効時の変更は `nettle-aes` の4箇所のみで、他18本は基準とバイト一致。無効時は19本すべてが基準とバイト一致した。
- 4箇所の引数捕捉、共有する燃料更新コード、分岐、残りのコード、再配置、テーブルを比較した。各対象箇所は65語から73語になり、合計32語増えた。故意に壊した8種類の命令を独立検査が拒否した。
- 専用命令単体をローカルのMacBookPro18,4で実行した。固定1,108入力すべてが元の復号テーブル計算と一致し、3種類の誤実装は事前指定した入力で検出できた。4ビルド・16実行の記録を保持した。

## 残る検証

専用命令単体の実行は、コンパイラが生成した呼び出しの検証とは別である。実際の呼び出しについて、6引数、呼び出し元の値、64ビットのモード判定、燃料不足時の更新順序、実行状態、容量不足とエラー経路を確認する。その後、固定した元19本とCイメージを同じホストで測定する。

今回の復号候補について、新しい性能測定値はまだない。前段の燃料更新候補の[測定結果](coscientist-resident-fuel-comparison-20261007.md)では、AESの時間は8.7483%短縮したが、Cの約9.9885倍だった。19本の候補/Cの幾何平均は7.249833で、全体の改善は確認できていない。これらは公式Embenchスコアではない。

## 証拠の範囲

値保存、生成コードの検査、専用命令単体の実行、呼び出しの実行、性能を別々に判定する。内容のハッシュと、実験設定・使用したコンパイラ・実行ホストの記録を分ける。規則が適用されたことやコンパイラが固定点になったことを、性能向上の証拠にはしない。
