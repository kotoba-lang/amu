## Design as built (deviation from the design's section 6)

The design proposed FK-IMPORT FN records, an FX-EXT fixup, an FN2 side table and a LINK region in M. The seed does the same
job with no SIR, ABI or FN-table change:

- **Import stubs.** For every interface entry of a required module, the importer's source is followed by a generated private
  defn named as the importer spells it (`u/bump`, or the referred name) with the export's checked signature, e.g.
  `(defn- u/bump [p0 :i64] :i64 (u/bump p0))`; an aborting export's stub body is `(throw <zero of E>)`, so 21-check infers
  `:abort` with E at every call (ADR 0363: the reference's `kotoba_import__i` stubs). Qualified symbols are then ordinary
  symbols. Before 20-names, 60-proj refuses an alias that is not required (`named operation zz/f is not a registered
  capability`) and a name that is not an export (`qualified call is not an admitted exported import: l/hidden`).
- **The module's ns form** is replaced by a generated `(ns <name> (:export [..]))`: the entry keeps its declared exports
  (root rules: i64 parameters, E2130 for an unhandled abort, measured = stage-0's text on feat/n09), a library exports
  nothing to the container (`(:export [])`), so an aborting, :string or multi-arity export is admitted; its interface is the
  link table.
- **Link.** Each module is compiled alone with M reset in between (`pj-reset`: every region's prefix up to its fill, the
  whole HASH and SCOPE regions, the HEAP up to its top, M[0..255]); its literal loads are relocated by its image base in
  42-layout; its blob is appended at an 8-aligned base; the first instruction of every stub clause becomes `b <export
  clause>` (a tail jump: x0..x4, x7 and lr are the caller's; fuel is charged by the export). Cost: one extra `b` per
  cross-module call.
- **State outside M**: a second vector L (2,097,152 items: module, require, refer, interface tables and the image, one byte
  per item) and a `[:list :string]` pool for paths, names and stub templates.
- **Reader conditionals** are selected in 10-lex: the first clause whose feature is `:kotoba` or `:default` is lexed, the
  others are passed by a lenient skipper (balanced brackets, strings, char literals, comments, `#"..."`, tagged literals,
  prefixes, metadata) that never classifies tokens; no match reads as nothing; `#?@` splices.
- Route: `compile` goes through 60-proj when `--source-path` is given, when the entry's ns form has a clause 20-names does
  not read (`:require`, an attr-map, a docstring), or when it spells a qualified symbol; otherwise the single-module
  pipeline is unchanged (G4: 84 containers identical to the R4 seed's).

## Limits and open risks

- Interfaces carry `:i64 :bool :string :vector-i64` and option/result/list/set/map of those. Keyword types (a keyword value
  is a per-module SYM index), records (identity per module), fn types and variadic clauses are refused at a module boundary
  (E6017). R6 needs a canonical cross-module keyword and record form.
- `def` constants are not importable (reference rule); the split carries the constants each namespace spells.
- The string pool P is a functional typed list: each added string copies it (one loader vector and O(n) items per add).
  Measured fine at this size (the split: about 500 strings); for R6 (126 modules, thousands of exports) it is quadratic
  in items and vectors (KEXE_VECTORS 65,536, KEXE_VECTOR_ITEMS 16,777,216): a mutable string table is needed before R6.
  The first version of the object writer hit `:vector-table-exhausted` on the split exactly this way (fixed with
  accumulators).
- `--policy` is accepted and not checked, `:capabilities` clauses are read and ignored (part B). `@x` is still E1005.
- `gates.sh --rung r5a` cannot run: its GR includes seed/tests/r5, whose case format gr.sh does not read (request in
  seed/CONTRACT-REQUESTS.md); gate-r5a.sh is the rung's gate meanwhile.
