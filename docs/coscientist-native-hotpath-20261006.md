# Native function-entry evidence with independent subagent verification

The preceding private-length placement experiment did not qualify a performance gain. This phase measures physical native entry frequency to select the next general rule. It changes a separate native Kotoba diagnostic generator and an owned diagnostic supervisor. This excluded new diagnostic algorithm is a one-off research authoring exception, not a mechanical product refactor. Product sources, original benchmark bodies, permanent expectations and the measured product remain unchanged.

The work was divided into three independent assignments: native implementation and machine audit; hand-known calls and live ABI controls; owned context and resource/trap controls. The root registered the selection protocol, checked counter arithmetic with SMT, independently replayed original19 source/function mappings and made the next hypothesis decision. Completed proof was shared between assignments; no additional performance campaign was launched.

The diagnostic compiler reaches a three-generation native fixed point: generations2/3/4 are **890,216 B**, SHA256 `2eb467cf0703ce468f580653fcf27d6fc3769f6896f42f89668b45852d63d239`. Its disabled generator emits product-exact bytes and offsets for all19 originals. The actual instrumented observer also reproduces the diagnostic targets exactly.

Qualification includes:

- All19 actual machines contain1,349 six-word entry blocks. Removing only those blocks preserves84,681 retained words,16,328 projected branch targets,188 literal words and289 private auxiliary destinations. Source/fusion ranges, frames and register metadata agree. Faults in opcode, counter ID, condition flags and private marker are detected.
- An owned supervisor appends the counter pointer after the unchanged400-byte context prefix. Context size becomes408;8,192 uint64 counters are separately accounted from guest arenas. Offset400 was the product result field, not spare space: the owning shared structure and all its consumers are rebuilt. Layout assertions and prefix comparison pass.
- Independent constructor controls compare220 actual full supervisor states across12 sources, including four invalid public handles. Thirty-six full-fuel cases have hand-known physical counts. Actual private-entry count omission/ID/skip faults are detected. Separate native counter probes execute IDs1/4095/4096/8191 and detect24 register/flags/ID mutants. The implementer's separate register probe covers24 executions and three faults.
- Original19 resource boundary comparisons pass161 full-state pairs, including46 traps and partial vector contents. Successful runs publish115 complete receipts; trapped runs publish46 prefixes. Four compiled supervisor mutants and malformed receipt controls are detected. Counter IDs must belong to the actual pinned artifact, which may have gaps.
- Supplementary SMT produces four UNSAT bounded-address/alignment/distinct-slot checks and three SAT unsafe-counterexamples. These are explicit arithmetic contracts, not a compiler, loader or authority theorem.

## Executed observations

All19 originals and every matrix input were executed: **95 untimed runs**, with exact product result/fuel/resource state parity. Depthconv's largest original input is2000; the other profiles are not substituted for that input. Each trace is bound to original source, diagnostic compiler/native/loader and actual FN/SIR metadata.

These are **physical native entries, not time shares or loop trip counts**. Self recursion lowered to a loop can have one physical entry despite multiple logical calls; an inlined helper can have zero physical entries while its computation runs. Counters have modulo-u64 semantics. Bounded hand-known controls establish their expected values, but no general wrap-free theorem is claimed. Interrupted/trapped runs are prefixes. Trace latency is not performance evidence, and this phase produces no new C ratio or official Embench score.

The root independently reconstructed all95 raw receipt mappings against the qualified product census and checked source/native pins, fuel consumption and complete state parity. ## Next registered hypothesis

[The prospective rule](evidence/coscientist-native-hotpath-20261006/next-hypothesis.json) targets a statically stable vector parameter in a closed read-only loop. A dominance witness may permit retaining validated length/data metadata across reads without checking a dynamic handle key at every read. The earlier dynamic-key loop-cache experiment was rejected; this is a separate proposed admission and lifetime proof. Actual spare register ownership and emitted read/loop behavior must be inspected before implementing it. If entry counts cannot support the selection, a finer qualified read/loop trace is required.

The rule must keep the first handle validation at its original access, all index checks, fresh item loads, original fuel charges and trap order. Missing dominance, changed vector locals, unknown/indirect calls, allocation, effects or unavailable registers refuse admission. Code growth remains bounded. Neither unobserved functions nor bounds checks may be removed on the basis of this profile.

Graph rules are selected by typed structure and rooted local matches, with explicit meaning-preservation contracts. Diagnostic/compiler/rule/ABI recipes have identities separate from semantic DefCID. No execution-result or capability memoization, TLC/TLAPS execution or universal compiler/authorizer proof is claimed. No product promotion follows diagnostic success. **C-or-better across full original Embench19 remains active and unachieved.**
