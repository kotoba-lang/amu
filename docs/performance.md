# Compile performance

Amu's compile-performance evidence separates process startup, loaded compiler
work, backend emission, artifact writes, and persistent-worker requests. A
single instruction timing or a warmed process is not reported as cold compile
speed.

Run the reproducible Wasm and host-native matrix:

```sh
npm run benchmark-compile -- --runs 5 --output performance.json
```

The `kotoba.performance-baseline/v1` JSON records every sample, median and
p95, artifact/provenance sizes, platform, architecture, Node version, and exact
compiler commit. The harness warms only dependency-classpath resolution before
cold samples; each measured cold compile starts a new launcher and compiler
process. Optional host-specific regression ceilings are:

```sh
KOTOBA_BENCH_MAX_WASM_MS=5000 \
KOTOBA_BENCH_MAX_NATIVE_MS=5000 \
npm run benchmark-compile -- --runs 7
```

There is deliberately no universal default ceiling: hosted-runner contention
and machine class are part of the result, not noise to hide.

### Development evidence

The implementation worktree was measured on 2026-08-10 with three samples on
Darwin arm64, Node v26.3.0, from base commit `045323e`. The report explicitly
recorded `compilerDirty: true`; these figures qualify the change under review,
not a released commit or a portable ceiling.

| Target | Cold-process median | Loaded compiler median | Artifact |
|---|---:|---:|---:|
| Wasm32 | 4,073.25 ms | 647.50 ms | 529 B |
| AArch64 | 5,269.59 ms | 732.07 ms | 4,768 B + 953 B provenance |

| Worker target | Startup | Unchanged cache-hit median | Policy-only change | Spelling-only edit |
|---|---:|---:|---:|---:|
| Wasm32 | 4,016.66 ms | 4.04 ms | 14.10 ms | 32.48 ms |
| AArch64 | 4,531.42 ms | 6.32 ms | 93.14 ms | 124.76 ms |

Worker rows include NDJSON round trip and artifact writes. Policy-only changes
miss the artifact cache, hit HIR/KIR, and rerun admission. Spelling-only edits
miss HIR but reuse byte-identical semantic KIR. The full JSON evidence is
generated by the command above; it is intentionally not checked in as a
machine-specific evergreen claim.

## Phase timings

Set `KOTOBA_COMPILER_TIMING=1` on an ordinary nbb-fast-path `compile` or
`check`. One stderr line prefixed `KOTOBA_TIMING ` contains a
`kotoba.compiler-timing/v1` JSON value. Normal stdout and artifact bytes do
not change. Timed phases include source admission/read, frontend analysis,
policy decoding, capability admission, KIR lowering, backend emission, native
sealing and independent verification, provenance, and writes.

## Target-specific entrypoints

The launcher selects the compiler dependency closure before Node loads it:

- `check` and `wasm32*` do not load either native emitter;
- `aarch64*` loads only AArch64;
- `x86_64*` loads only x86-64;
- policy bounds, diagnostics, timing, and exit codes remain shared.

This reduces target-irrelevant namespace load without changing the public
artifact, policy, or error contracts.

## Persistent compiler worker

A target-locked worker accepts sequential newline-delimited JSON:

```sh
bin/kotoba -M worker --target wasm32
```

After the `ready` response, a request carries ordinary CLI arguments:

```json
{"id":1,"args":["compile","examples/i64-semantics.kotoba","--target","wasm32","--output","/tmp/i64.wasm"]}
```

Shutdown is explicit:

```json
{"id":"shutdown","op":"shutdown","args":[]}
```

The protocol is bounded to 64 KiB per encoded line, 64 arguments, 4,096
characters per argument, and 1,000 requests by default. The request ceiling can
be set from 1 through 100,000 with `KOTOBA_WORKER_MAX_REQUESTS`. Usage,
decode, and admission errors are isolated to one request; an internal status-70
failure fail-stops the worker. Backend identity cannot change during a worker's
lifetime.

## Verified caches

Each worker owns two bounded in-memory LRUs.

The artifact key binds cache schema, exact target, exact source text, whether a
policy was explicitly supplied, and exact policy text. Wasm stores emitted
bytes. Native inserts only after admission, emission, sealing, independent
verification, and provenance generation. Every hit re-hashes cached artifact
and provenance payloads before writing. An integrity mismatch evicts the entry
and fail-stops. Defaults are 128 entries and 64 MiB, configurable with
`KOTOBA_WORKER_CACHE_ENTRIES` and `KOTOBA_WORKER_CACHE_BYTES` within hard
ceilings of 4,096 entries and 1 GiB.

The stage cache keys HIR by exact source text and KIR by serialized semantic
HIR. Policy is intentionally excluded, but capability admission is always run
against the current policy before KIR reuse. Thus a denying policy cannot be
bypassed by cached analysis. A spelling-only edit may miss HIR and reuse
identical KIR. Stage payloads are also re-hashed on every lookup and use
separate `KOTOBA_WORKER_STAGE_CACHE_ENTRIES` and
`KOTOBA_WORKER_STAGE_CACHE_BYTES` bounds.

`npm run test-compiler-worker` verifies target locking, protocol limits,
error recovery, byte-identical artifact hits, policy-dependent admission, and
HIR/KIR reuse. `npm run test-performance-baseline` verifies the report shape
with real Wasm and host-native compiles.
