# Aha-mont64 の符号なし比較：M4での結果（2026-10-07）

Amuで自己再ビルドした実験用コンパイラの比較置換は、元のAha-mont64で実行時間を20.19%短縮した。Cにはまだ届かず、候補の時間はCの1.23084倍だった。製品へは未採用で、全19入力のC以上という目標は未達成。

事前に固定した実行器・成果物・条件で、47組中30組を低負荷の条件で受理し、17組の除外も保存した。149プロセスは較正8回と測定141回。基準/候補1.25304倍で、事前の改善判定を満たし、C以上の判定は満たさない。過去の測定とは合算していない。

測定前に元入力を0・1・32回与えた基準・候補・Cの9回の機能確認を通した。[比較規則の実装と240回の有限検証](coscientist-charged-compare-20261007.md)、独立担当による全生データの再計算、親担当による[保存証拠の別ディレクトリでの再検査](evidence/coscientist-inverse-aes-20261007/charged-aha-timing/README.md)が揃っている。燃料・受理判定・集計を変えた3つの反例も検出した。

CはApple Clang 17.0.0の記録済み `-O2 -std=gnu11 -dynamiclib` ビルドと同じバイトだった。[19成果物の出所確認](coscientist-C-provenance-20261007.md)には各ビルド引数を保存した。コンパイラ本体・SDK・暗黙の環境は未固定であり、この独自の同一ホスト測定は公式Embenchスコアではない。作成時にC条件を不明とした封印済み記録は変更せず、後日の補足として扱う。

対象はAha単独。別のAES直接レジスタ候補は[0.65%差で改善を認定できなかった](coscientist-directreg-aes-comparison-20261007.md)。今回の数値を全19入力の新スコアや製品の改善率に置き換えない。次は、領域解放によるハンドル再利用・未知の呼び出しで解析結果を破棄する条件を含め、複数の入力に効くベクトル境界解析を検証する。
