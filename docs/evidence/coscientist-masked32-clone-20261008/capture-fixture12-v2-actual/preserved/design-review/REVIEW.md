# Independent bounded design review

The design correctly separates FD-only capture from strict memory admission. An inventory/identity/rusage failure still fails the gate; bounded retained bytes, both-pipe EOF or direct-child exit0 cannot restore qualification. Permanent group authority retirement before potentially reaping waits, no retry/poll/postwait operations, and independent capture/semantic/memory/closure fields preserve the required evidence boundaries. The saved ON cause is not proved: source shows how a sampling exception can stop capture before later available bytes are read, but no saved event trace establishes that ordering in this run.

The one-second drain is bounded by the existing absolute outer and cleanup deadlines; it grants no new child execution window. The FD worker must own reads, selector registrations and output writes, handle each stream fairly, preserve bounded prefixes and distinguish known overflow/dropped bytes from unread/unknown remainder. A quiet pipe is partial, not EOF. Cancellation cannot restore authority or cause cross-thread descriptor reuse.

Required concrete fixture before any fresh native proposal:

- Implement a capture object with one FD owner and explicit start/stop acknowledgement. Use nonblocking pipes and deterministic injected selector/clock/write/fsync events. Assert the sampler cannot block the worker, and a failing sampler followed by delayed/prebuffered stdout/stderr retains bytes within the original deadline.
- Demonstrate both-stream fairness, asymmetric EOF, cap+1 overflow, short writes, already-expired deadline, quiet open pipe, and cancellation. Worker should publish immutable capture status only after selector/FD retirement and writer stop acknowledgement. Include file write/fsync exceptions.
- Model threshold/budget refusal separately from identity uncertainty, and serialize watchdog signaling with authority retirement. Cover watchdog-before/after-retirement, direct wait kernel-reap/publication ambiguity and wait exceptions; record whether identity was established at each operation. Never infer group absence from EOF.
- Inject failed worker join. A bounded caller cannot force arbitrary Python thread termination; if it remains active, retain its FD/file ownership, expose captureClosure=uncertain, leave hashes unavailable and do not publish completion or continue another case. Do not close/reuse a descriptor still owned by that thread. Fsync/hash publication requires acknowledged stopped writer; metadata-only failure is permitted where capture/journal finalization fails.
- Confirm all failure paths preserve first-failure/no retry, direct-child closure uncertainty and permanent group-operation retirement. Test that complete equal ON bytes can be a partial semantic observation while memoryAdmission=false remains a failed gate.

The current pure model is intentionally smaller: five ownership refusals plus five capture-boundary checks. It does not implement a thread, two independent FDs, real absolute deadlines, short-write/fsync handling, journal transactions, or a cancellation handshake. Repeated sample-failure events can reset its drain ticks; the concrete fixture must make first failure monotonic and must not restart an absolute drain deadline. This is a model scope gap, not evidence the proposed operational design extends a deadline.

Disposition: design coherent for implementation, runtime HOLD pending separately frozen implementation and deterministic fixture/source review. No new native calls authorized or performed; no recovery of saved lost bytes. Soft footprint/transient/EOF gaps and lost-identity cleanup limitations remain.
