# Read-only descriptor caching across in-place writes

The current native scalar candidate remains unchanged. This investigation adds no optimizer, runtime counter, workload edit or timing campaign.

The loader and native emitter confirm that successful in-place association writes one element, returns the same handle and does not change vector metadata or allocate. A descriptor cache can therefore survive these element writes while every later read still loads fresh contents. First handle validation, bounds checks, fuel/trap order and partial writes must remain. Alias ownership is still the compiler checker's responsibility; the loader guarantees memory safety.

An exact same-local backward proof finds only two uncached mixed loop functions in huffbench, one already framed. A bounded forward must-alias prototype also follows local handle copies and finds six candidates across edn, huffbench and nettle-aes. Four already-framed candidates cover 17 static reads and 14 static writes. Ten excluded abstract controls check root copies, in-place updates, undefined loops, alternate joins and misuse of scalar read results as handles. These are feasibility results, not native admissions or performance evidence.

A second route can avoid added frames: huffbench FN21 has x3..x6 unused in source and free of actual body writes. Three registers could hold length/base/validity. The current allocator does not home low parameters merely because a leaf has a frame: slots1..7 remain x0..x6. Arbitrary low-register borrowing would be unsafe. Full operand/lifetime and entry/return sentinel proof remains required before implementing the spare-bank route.

Four existing-frame candidates would add saved registers and 16–32 frame bytes; the cold guard pattern adds two static words per access. A hit can remove ten executed access instructions, but no dynamic read/write frequency or speed share was measured. huffbench FN20 has only one spare low register; adding a new128-byte frame repeats the setup risk of prior rejected candidates and is excluded from this next route.

The broader gap needs region-level handle versions and effect/ABI invalidation proofs around calls and allocations. Preserving x7 alone is insufficient to preserve a descriptor or a scratch bank. Unknown capabilities, metadata mutation, allocation/arena invalidation and alternative handles require conservative fallback. Content identity can pin rules and proofs, but mutable vector contents cannot be memoized by handle/CID.

`report.json` records exact source/native applicability, ranked directions, finite bounds, first-access/fuel/alias/register obligations and adversarial cases. Adjacent scripts replay the excluded read-only analyses. `analysis.json` is the stricter same-local census, `alias-analysis.json` the bounded forward model, and `low-bank-audit.json` the conservative native write-bank census. All primary source pins were revalidated unchanged.

The parent reports four qualified gains in the current full19 campaign, with candidate/C geometric ratio7.6897; the user goal remains unmet. The largest gaps are picojpeg19.30x, statemate16.48x, edn15.21x and AES15.05x. `largest-gap-frontier.json` records why this mixedleaf rule cannot cover the whole frontier: Pico has49 ordinary nonleaf vector functions, while Statemate includes119 terminal leaf2 functions already using mode2/private ABI. Closed call-edge metadata lifetime and exact ABI proofs are a broader direction; existingmode2 must not be discarded or duplicated. These are static counts, not cost shares.

Three altered excluded-model faults are detected: all-predecessor meet weakened, unknown entry locals assumedroot, and scalar read result treated as unchangedhandle. Native compiler safety is still unproved for this proposed rule. The parent also identified a supervision boundary: the product loader can return successfully with remainingfuel0 after budget1, while a diagnostic loader traps afterreturn. Future proof plans must test the actual post-return product boundary and retain legitimate zero-remaining success; diagnostic state parity alone is insufficient.
