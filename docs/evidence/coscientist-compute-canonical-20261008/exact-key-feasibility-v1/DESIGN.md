# Exact-key reuse feasibility and next proof boundaries

This is saved-record/source analysis only. Keep complete C1 request and strict Result/transition identities unchanged. C2 remains OFF and every query remains direct. Current three cases are distinct subjects5/4/3, all within the same exact Snapshot; pairwise only subject and diagnostic case-id fields differ. There is no actually repeated same-subject request in this sample. The alternate requests are serialization controls, not query executions or cache hits.

The complete request includes work at field80, all preaggregate/status fields32..79, control256, contribution2048, lastkey512 and valid128. Successful actual logical charges are positive. Conditional on no reset/rewind of work between entries in one activation, the next request's work is larger, so its exact full Compute key cannot equal the previous key even when the four entry bounds match. This is source-dependent arithmetic, not an observed repeated-query schedule. Current shadow requires selected valid0; the ordinary successful V8 path publishes valid1. Existing activation-local V8 memo deliberately has a smaller four-bound key under frozen context and meets all outgoing contributions into changing aggregates. That does not qualify a global CID key or a C2 lookup.

A future separation must use three objects with separate contracts:

1. **Semantic query:** immutable sameSnapshot typed subject/dependency/read context + exact four entry bounds + every value read that affects contributions, support/poison, diagnostics or semantic control. Scope/rules/evaluator/ABI/trap/output contract remain pinned. Only proven accumulation/output roles may move out. Diagnostic case-id is a client witness header supplied outside the evaluator's M/f signature; moving it out also requires a new registered schema, not an edit to the old request. No global crosssnapshot DefCID normalization is available.
2. **Admission/transition:** current exact work/refusal/resource budget, preaggregate/status, memo-valid/lastkey/capture phase and all other current mutable admission inputs stay captured. Successful ordered replay starts from the actual current preaggregate and reproduces old target minima; -1 neutral and later0 remain. A semantic payload is insufficient authority to publish an old aggregate or stale poison/status.
3. **Result:** conservative projected ordered contributions/support/poison/diagnostics/logical charge. Compute-to-Result association and full transition receipt remain separate and valid-last. Same result can support later red/green propagation only after every downstream consumer dependency and authority contract is independently closed. Current serialization equality does not justify stopping downstream computation.

Minimum proofs before any field moves out of the semantic key:

- Full61-definition/read-role/reset/ownership proof distinguishes value-dependent reads from accumulation reads. In particular vw-arg-bound reads old target aggregate for a minimum update, and memo replay likewise reads old aggregates. Finite saved fresh/preaggregate parity alone is not a universal contribution-invariance proof. Callee alias/return summaries, candidate/mode and poisoning must stay bound until proven immutable or semantic inputs.
- Direct-on-independent-copies shadow compares ordered contributions and every retained status/diagnostic/charge for separately changed work, preaggregate, control and memo state one field at a time. Failures preserve first-error and no partial cached publication. These would be new preregistered native cases; no existing output is relabeled proof of the altered inputs.
- Resource admission requires exact remaining-work versus accepted charge, all caller caps, checked body/domain and frozen context; insufficient/unknown/partial receipts fall back to the original direct path. Do not assume only final counter equality preserves original intermediate refusal, VM fuel, scratch or capacity behavior. Replay's own work and hashing/sealing cost are charged. A separate internal accounting contract and full boundary/mid-transition controls are necessary before any skip; language/runtime observable fuel/traps/effects cannot be silently weakened.
- Prove all input and output lifetime/seal ownership, phase role reuse, valid-last and importer authority. Cold/warm/shared-OFF byte gates remain required; sharing stays disabled without exact snapshot/typed reference proof.

Measurement prerequisite: instrument actual repeated same-subject calls across representative original19 compiler analyses without changing workload or inference rules. Count exact existing Compute keys and a proposed semantic key only after the above proof. Measure context seal once, per-request encoding/hash/lookup, direct analysis and contribution replay separately, including failures and amortization. Current diagnostic charges include full8M-cell scans/copies, trace, codec/hashes and adversarial controls. They are logical conventions and not timings. No profitable hit rate or saved time is established.

Decision: **stop the exact-full-request-key cache-speed hypothesis at this checkpoint**. Preserve strict C1 as an evidence/admission identity. Continue semantic/admission separation only as a new bounded proof-and-measurement hypothesis, never by arbitrarily excluding resource/control/preaggregate fields. The user goal of C-or-better original19 performance remains unchanged.
