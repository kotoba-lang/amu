# Full30 native compiler adoption

The source compiled here is commit
`87fbc40e19a8bcab5e474a64c25c13bf5cf2e051`. The full manifest contains
30 modules, retaining all 18 adopted core modules. The root and public
compiler are generated by the native compiler, without a C compiler,
dynamic loader, old language host or emulation.

`one-compiler.json` is the unmodified receipt downloaded from GitHub Actions
run [40065864346](https://github.com/kotoba-lang/amu/actions/runs/40065864346).
It records the independent canonical Pw route, complete ARM F1=F2=F3,
source-lock controls and cross-built x86 compiler. `adopted-root.json`
records the local native ARM rebuild after updating the root: root=F1,
24 cases and browser Wasm compilation. The two `arm-native-*.json` files
record image/EFI diagnostics executed by that adopted root and its rebuild.

Review found that the original diagnostics required an ARM bootstrap with
at least two newly generated images. They could neither qualify native x86
generations nor run after root adoption. The corrected shared proof loader
accepts the actual complete native x86 receipt, or a measured ARM root=F1
fixed point, and checks source/image identity before any compilation.
`proof-controls.json` records actual refusal of false root reproduction,
source drift and a corrupted producer on the native ARM host.
The x86 workflow now executes both diagnostics and retains all three native
compiler generation binaries for independent readback.

`complete-x86.json` records actual native Linux x86 F1=F2=F3, matching the
new public image, current full source, all24 cases and pinned public-entry
refusals. `native-cdci.json` and the two raw self-hashing `.receipt` files
record fresh controller execution with both mandatory roles, all24 cases,
18 refusals and parent-death child cleanup. The controller/gate bytes stay
at their existing pins; their new compiler binding is the fresh receipt.
Clock/entropy and the native x86 boundary receipts are included separately.

That run's overall conclusion is failure: the old public image in its
checkout differs from the newly built compiler. It did not run the later
browser step or the new x86 AIUEOS diagnostics. `adoption.json` joins the
verified receipts and identifies this limitation. Exact-final-head CI with
the updated public image and target diagnostics, merge, and merged-main
verification remain separate acceptance gates.

The QEMU entry probe in `../aiueos-native-entry-20261024/` remains a bounded
historical entry proof. These receipts do not qualify the full kernel
dependency graph, ISR/live runtime, native GPT media, desktop or input.
