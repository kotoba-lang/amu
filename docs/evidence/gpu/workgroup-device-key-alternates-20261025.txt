## The change (kotoba.compiler.accelerator-targets, both reader branches)

- New row key :measured-device-alternates ('|'-separated string, parallel row
  shapes across the two readers; the wg-row builder gains the key). The :nvidia
  row carries "agx|tegra"; :apple/:intel/:amd carry "" (no evidenced siblings,
  the 2026-10-25 decision's rejection); :arm/:unknown stay key-less (host) /
  "" (kotoba row builder), unchanged.
- The key is read as a SET: the :measured-device fragment plus ONE alternate
  per non-empty '|'-field; a NAMED device keeps the row flag only when ONE
  name part carries every fragment of one set. nvidia = {xavier,agx} /
  {xavier,tegra}: "xavier" AND ("agx" OR "tegra").
- Kotoba arm: new key-hits / alt-any-hits / alt-field? / alt-end string walks
  beside substr-hits; recommend keys each name part through key-hits. Host arm:
  the same semantics (str/split on '|', empty fields contribute no set).
- Semantics pinned both sides: a trailing pipe must not widen the key
  ("agx|" behaves as "agx"); an all-empty key ("", "|") is the one-fragment
  set.

- The CUDA channel's reported name for the SAME physical host is
  `NVIDIA Jetson AGX Xavier` (row (iv)'s ground, commit 8fd09de4c).
- Row (iv)'s single-set key ("xavier"+"agx" in one name part) would REFUSE the
  workgroup channel's own attested name -- denying the measured device its
  flag under its own probe receipt. The alternate sets accept both spellings.
