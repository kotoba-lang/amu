JUN-58 / JUN-55 -- the exact-match gate class removed from the measure
harness's argv parsing (2026-10-23)

"LEFT (the next rows)" named first -- the residual exact-match gate class
in the harness's argv parsing (op-order `argc == 5`; harmless with today's

WHAT CHANGED (the diff):

- scripts/gpu-subgroup-reduce-metal-measure.m: the op-order gate
  `if (argc == 5)` -> `if (argc >= 5)`, with a comment naming the class.
  This was the LAST positional gate of the exact-match class in the
  harness: the `argc == 4` shape gate went dead the moment the op-order
  variable made the driver pass five arguments (the 2026-10-23 misshape
  defect -- every driver run silently measured the default shape until a
  run-log header exposed it; the mis-shaped cells are preserved under
  misshape-defect-20261023/ inside
  docs/evidence/gpu-subgroup-reduce-m1max-shape2-band-20261023/), and this
  `argc == 5` gate was the residual of the same class: correct today (the
  usage bound `argc > 5` refuses everything else, so `== 5` and `>= 5`
  accept exactly the same argv), dead the same way the moment a later
  positional lands behind the op-order. The fix is prophylactic: it makes
  the class structurally absent rather than accidentally harmless.

- test/kotoba/compiler/accelerator_variants_test.cljk: a new deftest
  the-measure-harness-argv-gates-carry-no-exact-match-class pins the
  class out of the harness source -- no `if (argc ==` gate form may
  appear (the match is the gate form, not comment text: the harness
  comments deliberately spell "NOT argc == N"), and the three positional
  gates must stay `if (argc >= 3)` / `if (argc >= 4)` / `if (argc >= 5)`.
  The misshape class had NO test guard before this pin.
