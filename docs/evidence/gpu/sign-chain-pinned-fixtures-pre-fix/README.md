## Why these bytes moved here

`test/fixtures/gpu/subgroup-reduce-w<W>-sum.emitted.glsl` is a **generated
artifact** of `kotoba.compiler.accelerator-subgroup-reduce/emit-glsl` and is
now regenerated in place from the fixed emitter (4b7a1ccb's named follow-up),
with `fixtures-match-the-emitter` in
`test/kotoba/compiler/accelerator_subgroup_reduce_test.cljk` asserting the
fixtures track the emitter. The chain, however, measures the **pre-fix**
variant arm — its sign series is defined over those bytes, and mixing
post-fix bytes mid-series would confound exactly the quantity under study
(the sign of variant-chunked minus baseline-chunked over time gaps).

## The rule for future chain runs (all ticks)

Before dispatching the pinned probe, run from the worktree root:

```
sh scripts/gpu-sign-chain-stage-fixtures.sh.txt
```

It copies these archived bytes over `test/fixtures/gpu/` and verifies all
four sha256s (fail-closed; a refusal is a refusal). The pinned probe then
sees the same fixture bytes every prior datum ran, self-printing the same
`sha256=a25a6931…` (w64) on its SHAPE line. The probe bytes themselves are
not touched. Chain worktrees are per-tick; `git checkout -- test/fixtures/gpu/`
restores the committed regenerated bytes if a worktree serves double duty.

## What this archive is NOT

- Not evidence about performance. It is input bytes for a measurement
  protocol.
- Not the emitter's output today. Today's output is
  `test/fixtures/gpu/subgroup-reduce-w*-sum.emitted.glsl` (post-fix),
  pinned byte-for-byte by the test suite.
- Nothing here flips `:measured?` anywhere; `kotoba.compiler.accelerator-targets`
  is untouched by the fixture follow-up.
