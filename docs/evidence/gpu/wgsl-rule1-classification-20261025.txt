WHAT CHANGED (implementation slice; no hardware, no measurement):

1. scripts/gpu_regime_classify.py, ADDITIVE ONLY (the MSL path --
   render_section / sign_classification / level_clusters -- is
   byte-identical, untouched):
   - parse_wgsl_measure_log(): parses the measure-log's `time` lines
     into per-run medians. RUN UNIT, the adoption's "per cell-arm run":
     one run = one cell-arm sampling block, (n, W, operator, metric);
     its per-run median = the block's median over its paired rounds of
     host submit->completion (the log's own `time` line). Duplicate
     blocks raise; a log with no `time` lines raises.
   - render_wgsl_rule1_section(): the rule-1 publication in the
     CHANNEL'S OWN NAMED METRIC -- host wall-clock submit->completion,
     milliseconds (not gpu-ns; asserted by test). Per metric (single =
     one dispatch per submit; batch32 = amortized over 32 dispatches;
     the two metrics NEVER mix in one clustering): the per-run baseline
     medians per operator, and the GAP-1.15 clusters named by host-ms
     range with run membership. Incomplete blocks (no baseline arm
     sample) are NAMED and excluded, never silently dropped. No rule-2
     sign verdict is rendered (rule 2's WGSL publication is UNIMPLEMENTED,
     its own later slice). Rule 4 unchanged: no :measured? flag, no
     workgroup row.
   - CLI: --wgsl-log <measure-log.txt|-> (stdin route for the harness).

2. scripts/measure-gpu-reduce-wgsl.mjs: the harness now collects the
   `time` lines it prints and, after the aggregate line, publishes the
   rule-1 section via `python3 scripts/gpu_regime_classify.py --wgsl-log
   -` (single clustering implementation, fed the printed lines so the
   section re-derives from the log text exactly). On classifier failure
   the log prints "claim-protocol-rule1: UNAVAILABLE -- ... a log
   without the rule-1 section is NOT a claim-protocol record" -- a run
   can never silently pass as claim-protocol.
