THE DESIGN ANSWER (DECIDED this row): the frame budget is NOT lifted.
frames-limit 32 is the LANGUAGE runtime's measured budget
(resources/kotoba/lang/limits.edn: "Interpreter call depth ... 32 lets the
deterministic budget answer first on the compiler's host for those shapes",
measured 2026-09-24; its copies live in kotoba-lang/osaho and siblings --
not GPU-owned). This track fits the budget instead -- the string-fold-ascii
precedent (2026-10-24): a language primitive replaces a hand-rolled walk.

CAPABILITY PROBE (w3_prim_probe.cljk, verbatim semantics):
  string-index-of "ab|cd" "|"        -> 2       "abcd" "|"  -> -1
  string-index-of-from "a|b|c" "|" 0 -> 1   from 2 -> 3   from 5 -> -1
    from 6 -> TRAP "string offset is out of bounds" (from must be <= n)
  string-find-byte "a|b|c" 124 2     -> 3       124 5 -> -1
  string-skip-blank "  ab" 0 -> 2   "ab" 0 -> 0   " " 0 -> 1 (= n)   "" 0 -> 0
  string-find-blank "a b" 0 -> 1    "ab" 0 -> -1
  string-contains? "abcd" "bc" -> true   "x" -> false
  string-split-count "a|b|c|d" "|" -> 4   "a|b|c|d|" "|" -> 5 (raw count)

WHAT LANDED (code + tests):
(1) split4 walks PIPE POSITIONS via string-index-of-from (O(fields) frames,
    was O(bytes)); span and count contracts unchanged (per-field spans
    start..p / start..n; raw '|'-split count, trailing empties count).
    i = p + 1 <= n holds, so the primitive's from > n trap cannot fire.
(2) blank-str? = one string-skip-blank (blank-walk DELETED -- it recursed
    per byte and trapped the budget on long device names).
PINNED SEMANTIC CHANGE (blank): the deleted walk checked {32, 9, 10, 13},
so a field of only \v(11)/\f(12) passed as non-blank (and parsed).
string-skip-blank is C isspace (adds 11 and 12) and REJECTS it -- the host
arm's str/blank? reading (Character/isWhitespace covers 11/12): this moves
the W3 arm TOWARD host parity. Non-ASCII whitespace stays the named
residual (neither arm walks it here; the wire is ASCII).
