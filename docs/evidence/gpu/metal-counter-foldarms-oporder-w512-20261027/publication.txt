## Regime classification (claim protocol rule 1, Metal counters channel)

Published by scripts/gpu_regime_classify.py (GAP-1.15). This channel's baseline metric is NAMED BY THE CHANNEL (the 2026-10-25 counter-channel adoption and its harness/calibration rows, ADR-0360): counter_ns -- the GPUTimestamp counter-sample delta bracketing one dispatch ([encoder start, encoder end], GPU ns, the AtStageBoundary pass-attachment bracket; the instrument prints the raw pair beside every delta). The 2026-10-25 calibration row MEASURED that this delta carries an additive encoder-boundary residual on this host (counter_ns = T_dispatch + R(grid shape, state) + epsilon), so a level here is a BRACKET-DELTA level, not a pure kernel time -- the residual is named, never subtracted (no correction is designed).

Run unit on this channel: the MSL channel's, unchanged -- ONE FRESH PROCESS (the ADR-0358 protocol: fresh processes, interleaved AB/BA pairs, WARMUP=2 discarded, verified read-back). One log is one run; the per-run baseline median is the median over that run's resolved baseline-arm counter_ns samples for the operator; rule 2's unit is the run's paired-median ratio (median over the run's pairs of the within-pair ratio variant_ns/baseline_ns, NEVER re-oriented).

Clustering rule GAP-1.15: per operator, the per-run baseline medians sorted ascending, single-linkage -- the next median joins the current level at <= 1.15x the previous, else it starts a new level. The rule is metric-parametric as written (its 1.15 window derives from the MSL corpus's decided separation and carries unchanged); only the publication names the metric. Rule 2's sign classification is published in its own section beside this one -- this rule-1 section itself renders no sign verdict.

Rule 3's boundary stands: counter_ns merges with NEITHER the MSL campaign's command-buffer GPUStartTime->GPUEndTime bracket's gpu-ns NOR any host wall-clock (three instruments that all say "ns", never merged). Rule 4 is unchanged: this publication moves no `:measured?` flag, no selection answer and no workgroup row.

## Sign classification (claim protocol rule 2, Metal counters channel)

Published by scripts/gpu_regime_classify.py from the run blocks' paired-median ratios (rule 2's unit on this channel: median over the run's pairs of the within-pair ratio variant_ns/baseline_ns -- the ADR-0358 paired-within-run statistic, NEVER re-oriented) and the rule-1 regime clusters of the same runs' baseline per-run medians (GAP-1.15, counter-ns). Rule 2: a sign is regime-invariant when every per-run ratio of every observed regime lies on the same side of 1.0 -- only such a sign may be a selection basis; any other sign is regime-scoped and cannot choose a variant. The sign machine is the MSL channel's, unchanged and metric-parametric.
