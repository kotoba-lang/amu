WHAT LANDED (implemented, with tests):

- scripts/gpu_regime_classify.py, cross-operator identity machinery:
  - cross_operator_level_identity(per_op): the mechanical test. Rule 1
    classifies per operator, leaving the cross-operator question open
    (is a run's regime operator-independent?). The test is PARTITION
    AGREEMENT: for every run pair, every operator must agree on whether
    the two runs sit in the same rule-1 level (GAP-1.15, applied per
    operator). Agreement on every pair -> "identity holds"; any
    divergent pair -> "identity refuted", the pairs NAMED with every
    operator's relation (same-level / split-level). The disagreement's
    shape is published too: partition refinement between every operator
    pair (equal partitions / one refines the other / cross-cutting).
    Refuses < 2 operators, < 2 runs, and a run-set mismatch across
    operators.
  - render_identity_section(...) + render_section() wiring: the
    publication. The section is appended to the single-record output
    (and therefore to every future summary.md the measurement driver
    writes) when the record has at least two operators. `via` names the
    publication path (rule 3's honesty rule, applied here too).
  - The stale "NOT asserted" prose in the rule-1 header, the rule-2
    header and the pair-level header is updated to say exactly what is
    and is not asserted now (see WHAT IT DOES NOT DO below).

WHAT THIS SLICE DECIDED (the GAP-1.15 ethos: mechanical, visible,
pinned):

- Identity is partition agreement at RUN level, nothing more. The
  harness reads no GPU clock: "identity" is agreement of the run
  partitions, not verified clock identity. Where identity holds, a
  record's prose MAY name one level across operators; where it refutes,
  per-operator level names stay operator-scoped (one operator's fastest
  level is not another's).
- Rule 4 stands, unchanged and restated in the section's own text: the
  identity verdict is a publication fact. It changes no rule-2 verdict
  (the rule-2 cell row is still only the admissibility roll-up), no
  rule-3 phrase, no selection answer, no :measured? flag, no workgroup
  row.
