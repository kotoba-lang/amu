2. THE "THREE-STATE" SEMANTICS DECISION (DESIGN DECISION, this
slice; ACCEPTED DESIGN ONLY -- IN DRAFT, NOT frozen)

(a) THE NAME IS A BLOCK-COUNT NAME AT LETTER GRANULARITY
(adopted): "a three-state control record" MEANS exactly: the
record's four C1 letters form THREE state-BLOCKS -- a state-BLOCK
(epoch) being a maximal run of consecutive readings carrying the
same C1 letter as the current control state, a new block opening
whenever the letter changes -- and the record's block reading is
exactly (b) | (a,a) | (b): the 16th cut's (b) epoch, the
17th-18th cuts' (a) epoch (the 17th's (a) REPLICATES at the 18th
-- "no supersession needed", 1(d) quote -- so the two (a)
readings are ONE epoch), and the 19th cut's (b) epoch. Rationale
(design reading): the name's parenthetical enumerates exactly
the four readings' letters and nothing else (1(a) quotes); the
record's own state machinery counts "current control state"
epochs by exactly this rule -- consecutive equal letters
REPLICATE into one epoch ("no supersession needed",
publication-s197 L636-639) and a changed letter SUPERSEDES and
opens a new epoch (publication-s185 L630-633); under that rule
the four readings (b)/(a)/(a)/(b) count exactly three epochs,
which is what the frozen name counts.

(b) THE COUNT IS AN OCCURRENCE COUNT, NOT AN IDENTITY COUNT (the
boundary this decision exists to draw): "three-state" counts
three state-OCCURRENCES (blocks) over the s218 alphabet {a,b}
(ADOPTED UNCHANGED) -- it does NOT assert three distinct
underlying instrument states. The record establishes exactly TWO
letter IDENTITIES ((a) and (b)) across its three blocks (the
letter is a function of m against the band only -- letters-
s218.txt L72-76 shape, carried); whether the two (b) blocks (the
16th's and the 19th's) are ONE underlying state recurring or TWO
different states that both read (b) is NOT decided by any letter
and NOT decided by the name -- the s216 hazard (1(f) quote):
whether m 30 is a NEW control state or a tolerance/defect
reading stays UNDECIDED and is the resolution measurement act's
own business. NAMED, NOT HIDDEN: the name therefore asserts
THREE blocks / TWO letter identities / an UNMEASURED underlying-
state count -- under the s216 hazard's own two readings the
underlying count admits 1 (both (b) blocks tolerance/defect
around one state) or 3 (each block a distinct state) and every
reading between; the name constrains NONE of these and the
underlying-state count is never read off the name.

(c) REJECTED READINGS (named, not hidden):
  (i) "three-state" = THREE DISTINCT INSTRUMENT STATES --
  REJECTED: it would require either a three-letter alphabet (the
  s219 4(b) shape: a new symbol "has no counterpart in the

  cause measurement the record does not contain (the discrepancy
  cause stays UNMEASURED, L2 binds -- 1(a) quotes); the letters
  do not encode WHY a reading is (b) (letters-s218.txt L222-224).
  (ii) "three-state" = the bare claim "at least two states" --
  REJECTED as the name's MEANING: the frozen name carries the
  count "three" tied to its parenthetical four-reading record
  (1(a)); but NAMED, NOT HIDDEN: at IDENTITY level the record's
  own statement IS exactly "at least two" (prong B, 1(e) quote)
  -- the count "three" is meaningful ONLY as a block count, and
  this decision does not stretch it to identity.
  (iii) renaming the record ("three-block control record") in
  the pre-registration -- REJECTED: the name is frozen committed
  bytes carried verbatim (1(b)); this pre-registration confronts
  the record, it does not rewrite it; the decision FIXES the
  name's semantics instead of replacing the name.

ACT:

  quote). Under this decision: prong A (SINGLE-STATE STABLE) is

  so the act confronts the name at block-count granularity
  without any identity over-claim.
