THE QUESTION (verbatim, the deferring record's own terms --
docs/evidence/gpu-simdgroup-reduce-m1max-resweep-20261024/w32/NOTES.md,

  "Whether same-day re-session records are named in the flip note /
  basis evidence lists at all is a decision this tick does not make; if
  made, the naming is its own slice."

THE DECISION, two loci, two answers:

1. FLIP NOTE PROSE (kotoba.compiler.accelerator-variants'
   apple-simdgroup-flip-note): NAMED. A same-day re-session record is
   named in its own scoped paragraph, in the cross-day paragraph
   pattern, carrying exactly the scoping its own record carries:
   - it is NOT a cross-day replication (the contract's temporal row is
     later-day-only: "Cross-day replication of any cell needs a
     later-day run (a cron tick on another day), not more same-day
     sessions");
   - it extends no :measured-cell record's :shapes (a re-session runs
     the shapes the cell already carries);
   - it moves no :measured? flag, no selection answer and no workgroup
     row (ADR-0355/0358);
   - its magnitude phrases are regime-scoped WITHIN THE DAY (its own
     finding, below). Named, not hidden -- the campaign's rule is that
     a real session is recorded and scoped, never omitted.

2. BASIS EVIDENCE LISTS (apple-simdgroup-measured-evidence and the
   :measured-cell :evidence maps): NOT NAMED. The lists are closed
   under the flip contract's record kinds: each cell's own
   contract-satisfying flip runs (one per measured shape) and its
   sanctioned cross-day replication runs (corroboration that "flipped
   nothing"). A same-day re-session is neither kind: the protocol
   excludes same-day sessions from the temporal row, it flips nothing,
   and it extends no shape. Its sign corroboration duplicates the sign
   basis the cell's own flip run already carries. The naming
   implementation slice tightens the lists' docstrings to say "the
   flip contract's record kinds" explicitly, so the closed-under
   reading is stated rather than inferred.

GROUNDS (cited, previously recorded -- no measurement ran here):

G1. The protocol's own words (the record's cross-day rule, quoted in
    the anchor replication record's NOTES): "Cross-day replication of
    any cell needs a later-day run (a cron tick on another day), not
    more same-day sessions." A same-day re-session is a record kind
    OUTSIDE the contract's rows by the record's own protocol; the
    lists name the contract's rows.

G2. The W = 32 re-session's own measured facts
    (docs/evidence/gpu-simdgroup-reduce-m1max-resweep-20261024/w32):
    the sign replicates same-day (rule 2 REGIME-INVARIANT FASTER,
    18/18 per-run ratios below 1.0 in both sessions) but the magnitude
    and the regime structure do NOT -- raw paired medians moved 0.021
    (:sum) / 0.033 (:max) / 0.081 (:min) within one calendar day
    (0.636/0.691/0.731 vs the wsweep session's 0.657/0.658/0.650) and
    the cross-operator level identity flipped from HOLDS (wsweep: 0/15
    divergent run pairs) to REFUTED (the re-session: 12/15). A
    same-day second session therefore licenses nothing the first did
    not, and its own finding is exactly the magnitude instability that
    a "basis evidence" position would misread as license.

G3. The lists' semantics as last widened (the cross-day naming slices,
    2026-10-24: the anchor's and the W = 512 cell's): the lists moved
    from "flip basis" to "flip basis + the contract's SANCTIONED
    cross-day replication (it flipped nothing)". The widening names
    the contract's own replication row -- not "every run that ever
    happened". A same-day re-session is not that row.

G4. De facto state, verified this tick (search over src/: 0 matches
    for "resweep"): no same-day resweep record of EITHER family
    (docs/evidence/gpu-subgroup-reduce-m1max-resweep-20261023/ or
    docs/evidence/gpu-simdgroup-reduce-m1max-resweep-20261024/) is
    named anywhere in code today. The decision turns an inherited
    silence into a decided policy; it removes no existing name.
