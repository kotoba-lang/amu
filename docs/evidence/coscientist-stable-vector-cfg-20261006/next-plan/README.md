# Read-only next optimization plan

The independently audited successor improves XGBoost by 10.3653%, but remains 6.6154 times C. QR has no qualified gain. This directory proposes further general rules; it does not implement or measure them.

The strongest broad next investigation is bounded pure scalar DAG inlining: 11 eligible functions across five original workloads still have 132 actual native BL sites. Closed-edge proof, caller register ownership and a strict code-growth budget are necessary. Generic exported/addressable bodies must remain available. This differs from the rejected blanket private-length cloning experiment.

An exact fuel/backedge fusion has 54 native sites across 16 workloads. It preserves fuel subtraction, zero publication and trapping, and saves one branch. Successful-validation dominance permits 11 guard eliminations in the two current admitted functions, saving only one executed branch per later read; static removal of a skipped capture block does not imply proportional speedup.

XGBoost also has a concrete four-instruction affine index calculation that could become one instruction using an internal biased scalar representation, without another cache register/frame. Whole-function scalar-use and selftail-copy proof is required. The optional SMT replay could not run because z3 is missing; no solver result is claimed.

C stores the fixed XGBoost arrays in 39,555 bytes; Kotoba's state uses 316,528 bytes including mutable counters. The roughly eightfold representation difference is established, while cache misses and time attribution remain unproved. Readonly narrow-region layout and affine views are a larger architectural hypothesis requiring ownership, alias, identity, budget and low-fuel-prefix proofs. Constant-data construction work is an intercept rather than evidence for the repeated body slope.

`report.json` contains ranked hypotheses, exact applicability, proof obligations, finite-analysis limits and counterexamples. `analysis.json`, `fuel-census.json`, and `scalar-census.json` contain the observed details; their adjacent scripts replay the excluded read-only analyses. Baseline invocation counts are modulo-u64 counts, not time shares.

Prior clone machine audits found no loss of wrapper/tree/mode2/private-ABI/fusion behavior, but established major code growth and layout movement. Their negative timing is retained. Interleaving alone also failed qualification. Neither experiment establishes an instruction-cache cause.

The fuel census diagnostic was corrected to exclude a final partial literal-pool word from word unpacking. Candidate/source/binaries were never changed. No optimizer, counter, benchmark input or timing campaign was added here.
