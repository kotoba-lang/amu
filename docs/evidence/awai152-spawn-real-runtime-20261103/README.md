# Linux ARM64 direct-child parent-death observation

This is an isolated runtime test, not compiler self-host qualification. `stage.py` injects the candidate ARM64 runtime region into the measured base compiler, preserving the embedded source length and checking both compiler hashes. The base source is `seed/77-aarch64-static-rt.kotoba` at `7a755126`; the candidate is at the `sourceCommit` in `receipt.json`. Only comment lines are dropped to create space. The test-only compiler is not a release artifact.

In a disposable 1 CPU / 2 GiB Linux ARM64 VM, place the base compiler, staged compiler, `fixture.kotoba` and `observer.py` in `/private/tmp/awai152-kernel-check`. Compile the fixture with each compiler using `compile fixture.kotoba --target aarch64-linux --output <name>.elf --format static`, with filesystem resource 35 scoped to that directory. Name the emitted guests `baseline.elf` and `candidate.elf`. Run `observer.py` there; it grants wire 20 only `/usr/bin/sleep`, waits for the guest/helper/sleep ancestry, kills the guest, checks observed PID identity and liveness, and cleans up its own surviving test processes. `receipt.json` records measured hashes and outcomes. The Python files are test staging and observation only, not an operational component.

This does not establish whole-tree termination, macOS behavior, scheduling safety, race completeness, production governor qualification, or a native compiler rebuild. A program may fork or alter its signal. The x86 runtime, normal and refused spawn, and actual source/compiler identity gates still need separate verification.
