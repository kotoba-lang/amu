# Amu-generated scalar code executed by macOS

On an Apple Silicon Mac running macOS 26.4, the pinned Amu-built native ARM
compiler (`seed/bootstrap/aarch64-linux-static-root.elf`, SHA-256
`285c54f826d5f7f77db6827bc21c622c2c777cea252a1ba4816d8b01351807e1`)
compiled `seed/macos-generated-main42.kotoba` and
`seed/macos-generated-main43.kotoba` with `--target aarch64-macos`. The compiler
returned 34-byte `.kseed` artifacts. Its `extract-native --symbol main` command
returned a 12-byte zero-arity function for each source. The first instruction
differs (`mov x0, #42` versus `mov x0, #43`); both functions end in `ret` and
`brk`. A repeat compile of the 42 source was byte-identical.

`seed/macos-generated-main-smoke.kotoba` is a Kotoba source packager. It reads
the raw function through the FS2 file capability, checks its length, writes a
16 KiB arm64 Mach-O with the generated bytes at file offset 1040, and verifies
the FS2 write acknowledgement. The four instruction wrapper at offset 1024
calls that function and passes its return value to the Darwin `exit` syscall.
The packaged unsigned images have SHA-256
`966d5aef04d99fe954bd778421386f1ad5db8ce98117120d0c8ab8f421d85bfa`
and `7dd9ed4b207e6f6328c340561a4f0fbaa553125f288ba7b4d417d3178cfec751`.
The packager refused an 11-byte truncated function with exit 2 and produced no
image.

`scripts/seed/check-macos-generated-main-smoke.py` pins the compiler, source,
packager, `.kseed`, raw function, and unsigned image digests. It checks the
Mach-O layout and that the payload bytes equal the extracted function, signs
copies with the platform's ad hoc `codesign`, verifies the signatures, and
launches both images. [receipt.json](receipt.json) records actual empty
stdout/stderr and exit values 42 and 43. The Mac host observer provides no
compiler or packaging implementation.

The build used an existing local Podman Linux VM only as a host for the pinned
native Linux ARM compiler and Kotoba packager; all builds were admitted through
`scripts/seed/native_build_queue.py`. The test proves a narrow selfhost
`aarch64-macos` scalar codegen-to-execution path. It does **not** prove a Mac
native compiler executable, general relocations, full Amu runtime, capability
calls from generated code, self-rebuild on Mac, Itonami, AIUEOS daily use, or
Linux-free build closure. Those remain open on JUN-417 and the AIUEOS roadmap.

Reproduction sequence (with a new artifact directory mounted at `/work` and
`seed/bootstrap` mounted read-only at `/compiler`):

1. Compile each `seed/macos-generated-main{42,43}.kotoba` using the pinned root:
   `compile /work/<source>.kotoba --target aarch64-macos --output /work/<stem>.kseed`.
2. Extract each function with `extract-native /work/<stem>.kseed --symbol main
   --output /work/<stem>.raw`.
3. Compile the packager as a Linux ARM static executable using
   `compile /work/macos-generated-main-smoke.kotoba --target aarch64-linux
   --output /work/macos-generated-main-smoke.elf --format static`.
4. Run that executable with the output image and raw function paths as its two
   arguments, granting FS2 only the artifact directory. Repeat for 42 and 43.
5. On the Mac, run `python3 scripts/seed/check-macos-generated-main-smoke.py
   ARTIFACT_DIR NEW_OUTPUT_DIR`. The new output directory receives signed
   diagnostic copies and a fresh receipt.
