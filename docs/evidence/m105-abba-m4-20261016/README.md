# M105 full-suite ABBA repeatability on Apple M4

Status: **four CPU-gated, exact 19-workload campaigns completed; version effect remains confounded by timing drift**.

This follow-up reran the verified M105 baseline and current selfhost candidate in
`B1, A1, A2, B2` order. Each campaign used the pinned Embench IoT upstream,
the same Apple clang 17 C binaries, the official Kotoba timing harness, and
the round's exactness and CPU-idle gates. Every round accepted all 19 Kotoba
and all 19 C workloads. `analysis.json` is regenerated from each report and
raw sample; `raw-records.tar.gz` preserves the source reports, raw JSON, and
shared C build receipt.

## Results

| Campaign | Arm | Kotoba/C geometric mean |
|---|---|---:|
| B1 | M105 baseline | 0.77509 |
| A1 | M105 candidate | 0.80695 |
| A2 | M105 candidate | 0.77271 |
| B2 | M105 baseline | 0.74400 |

The geometric mean of the two baseline campaign results is **0.75939**; for
the candidate it is **0.78965**. Their ratio is **1.03984**, which would look
like a 4.0% candidate regression if the campaign scores were stable. The raw
per-workload times show why that attribution is premature: the candidate and
baseline generated byte-identical native images for 14 workloads, yet the
candidate-period Kotoba times for those same images are 3.1% slower in
geometric mean. The shared C arm is also 2.0% faster during the candidate
period. These shifts account for much of the normalized difference.

Only five native images differ between the compiler arms. Their candidate to
baseline Kotoba elapsed-time geometric mean is 0.99337. `xgboost` improves
while the other changed workloads are near parity or slightly slower. The
per-workload values and all four CPU-gate minima are in `analysis.json`.

This is a controlled translated-port comparison, not an official Embench
score or a SPEC result. Two campaigns per compiler are enough to expose the
timing drift, but not enough to establish small per-workload changes. The next
compiler experiment should isolate reciprocal division, MSub fusion, and the
xgboost change using their pinned selfhost compiler artifacts.

## Reproduction

From the repository root:

```sh
python3 docs/evidence/m105-abba-m4-20261016/analyze-abba.py
```

The raw campaigns are stored under the four `timing-*-m4-clang17-*` folders.
Host facts are recorded in `host-context.json`; the common C binary build is
bound by the receipt hash in `analysis.json`.
