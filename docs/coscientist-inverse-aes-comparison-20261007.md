# AES復号候補とCの性能比較（2026-10-07）

Apple M4（Mac16,10、zebulun）で、燃料更新候補を基準に、AES復号を専用命令へ置き換えた候補と同一のC成果物を比較した。AESは1.8453倍、実行時間45.8090%短縮した。ただしCの5.4905倍の時間で、C超えは未達。その他18本に事前基準を満たす改善・悪化はない。製品の既定設定には採用していない。

これは元19入力の同条件比較で、公式Embenchスコアではない。元C成果物のコンパイラ・全フラグは不明のまま扱う。

## 実験条件と証拠

各入力30組の基準・候補・Cを、順番を回転させて測定した。最大90試行、校正は各構成最大5回、目標300 ms・最短50 ms。負荷4以下、推定バックグラウンドidle 90%以上を組全体に要求した。相対標準偏差10%以下、速度比1.05以上、平均差が両標準偏差の和を超える場合だけ改善・悪化・C超えを採択した。

1回のキャンペーンで866組を試行し、570組を採用、296組を除外した。校正151プロセスを含め全2,749プロセスの引数・終了状態・標準出力・燃料・CPU状態を保存した。再試行によるキャンペーンの作り直しと、過去の統計の混入はない。独立担当は全生データの採否と平均・標準偏差・判定を再計算し、親担当も全135出力ハッシュを照合した。

入力ソースとCのバイト列は基準・候補で固定。変更はAESの4箇所だけで、他18本のネイティブ出力はバイト一致した。測定前に同じM4で19ホストのビルドと57件の機能確認を通した。実験用コンパイラはAmuによる4世代の自己再ビルドでバイト一致したが、製品全体のセルフホスト完了を意味しない。

有限入力の結果と報告される最終状態を確認した範囲であり、ABI全体・未報告の全メモリ・非同期更新途中・生成後半のエンコーダー拒否を網羅した保証ではない。

[実装・機能検証の詳細](coscientist-inverse-aes-20261007.md)。[保存証拠と3ファイルだけの再検査手順](evidence/coscientist-inverse-aes-20261007/timing/README.md)を公開用にまとめた。親担当も別ディレクトリで再検査し、57件の機能確認と全2,749プロセスを再計算できた。

## 次の仮説

直接レジスタを使う別候補では、AESの4箇所で各7命令を削減し、4世代の自己再ビルドと19入力の生成・独立命令列比較を通した。[実行時の有限検証](coscientist-directreg-20261007.md)は566件を確認した。入口拒否3件を含む3つの手順を区別して保持している。[別のM4測定](coscientist-directreg-aes-comparison-20261007.md)では差0.65%が事前の改善基準を満たさず、性能改善を認定できなかった。統計は今回の復号候補の測定と混ぜない。

広い処理区間で燃料の再読み込みを減らす案は、保守的な区間探索で複数の燃料更新を含む対象が見つからなかった。小さな純粋関数についても既存DAG規則にはCALL・分岐などの壁があり、燃料更新を保った呼び出し・CFGの変換規則と検証条件を先に設計する。命令数だけから速度向上は主張しない。
