## Owner decisions adopted this wave

1. First 100% is aarch64-macos only. x86-64, wasm, component, EVM, JS, uefi and the elf/pe backends are deferred.
2. A `.kexe` run by the C loader counts as the amu binary for milestone 1.
3. The native value-size limit is raised from 64 KiB to at least 8 MiB by ADR (0362).
4. The KIR interpreter is frozen: only `kir/lower` plus the evaluation `fold-def-value!` needs is in scope.
   (`fold-def-value!` keeps its real pre-checks; the evaluation itself is refused as `kotoba.fe/unported`.)
5. The JVM native-image checker is the stage-0 bootstrap compiler (bootstrap-reference).

Progress is the LEDGER below: definitions with a real Kotoba body that agrees with the host, not "files OK".

## Design

- Dual-route modules. Each host `defn` becomes `#?(:kotoba <Kotoba defn> :default <host defn>)`; host text is byte-identical.
  Host forms with no Kotoba reading are wrapped `#?(:kotoba nil :default ...)` so the module still checks.
- Values are `:form/r` Form trees. Lists are `[:list [:ref :form/r]]`; maps and sets are Form kids lists with linear lookup.
- Every loop is index recursion. Host volatiles and dynamic vars become values: counters, the `:fe/env` record, the `:ie/ctx` record,
  and Form-map state records (`:ana/r`, `:ana/rl`, `:ana/g`, `:ana/ir`, `:ana/ird`).
- Refusals are `(throw (fe-error ...))` of `:fe/err`. State-ability threading is defunctionalized CPS (eleven continuation kinds as Form maps).
- Imported aborting functions are typed `[:result T E]` by the checker; each is wrapped once (`an-c-*-caught` via `match-result` into `:ana/ir`/`:ana/ird`)
  and re-thrown in tail position of the same module.
- The analysis driver is `an-expand-source` -> `an-namespace-info` -> `an-constants-stage` -> `an-parts-stage` -> `an-desugar-loop` ->
  `an-stage-lambdas` -> `an-stage-passes` -> `an-stage-finish` -> `an-hir-gate`; `analyze` answers `:ana/ir` {ok val err}.

Checker findings worth keeping (each cost a bisection):
- A bare `(throw (record-new [:ref :fe/err] ...))` gives the thrown value an unknown error type ("two different error types ... nil"); throw a value
  built by a function whose result is annotated `[:ref :fe/err]`.
- A nested aborting call as an argument of another call (or inside `form/form-vec (...)`) is hoisted and reads as an unbound symbol; bind it first.
- Two `_` let bindings are "duplicate let binding"; use distinct names.
- A host-only constant (`#?(:kotoba nil ...)`) referenced from a Kotoba arm surfaces as "call to aborting function ... neither catches it".
- `(= bool bool)` is false for false/false on the Kotoba route (fixed in `namespace_defs`, below).

## Results of the linked end-to-end check

Programs: the first 30 programs of the recorded corpus plus a stride sample (every 4th of the remaining, 58 programs), 88 of the 263 recorded.
Each ran through `an/analyze` on the Kotoba route (JVM KIR interpreter) and was compared with the host HIR / refusal with `form/eq`.

| outcome | programs |
|---|---|
| same HIR / same refusal as the host | 79 (30 of 30, then 49 of 58) |
| different answer | 2 |
| interpreter trap | 7 |

The sample is not yet the whole corpus (the 263 programs take about 2.5 h at three processes); it is representative by construction (stride) but the figure is
79/88 (90%), not a corpus-wide proof.

First refusals / disagreements, in the order they were found and what they were:
1. Every guest answer was "refused" with an empty message: the `:ana/ird` record used its `:ok` field both as success and as the local-state flag, so an
   unset flag looked like a failure (fixed: a separate `:flag` field).
2. "function call arity mismatch: f takes 0 arguments": the Kotoba `validate-expr` takes a name -> arity table, the driver handed it name -> params (fixed: `an-arity-table`).
3. `namespace_defs` `nd-select-refer` compared two bools with `=`, which is false for false/false on the Kotoba route, so every namespace clause was dropped
   (exports were nil). 12 of the first 43 sampled programs disagreed because of it. Fixed in kotoba-sema (minimal edit, committed): the bool comparison became an `if`.
4. Seven programs trap with `list-index-out-of-bounds`; all seven use the slice carrier (`[:slice :u8]` parameters, `slice-of-u8`, `slice-get`, `slice-load-u8`,
   `slice-of-u16`), so the fault is in the slice erasure of `namespace_defs` (`erase-slice-values` and its `nd-*` helpers), a module outside this task.
   Not yet localised; sample line numbers 35, 36, 37, 39, 41, 42, 43 of `/tmp/claude-501-e2e-s.txt` (cases 35-43 of the stride sample).
5. Two remaining disagreements: (a) a program whose named-operations set contains a duplicated `:fs/app-data-bytes` (a set union that does not dedupe in
   `an-stage-finish`'s `used-caps`/`named-ops`), and (b) the refusal order for an entryless library with an invalid function name (the guest reports "invalid function name"
   first; the host reports the missing export list).


## Walls (measured)

- Linked-project limits: 1024 exports, 32 schemas. The e2e guest links because the JVM interpreter route is not subject to the checker's per-project export cap;
  the native checker cannot yet check the linked program as one project.
- Lowering the linked frontend takes about 5 minutes and about 2.4 MB of EDN; each guest change pays it once (cached by hash).
- A trap in the interpreter (`vector-index-out-of-range`) loses the whole batch; `e2e-diff.sh` therefore also supports `GUEST_FILE`/`ENTRY_FN`, and
  one-case-per-process runs isolate traps.
- `fold-def-value!` evaluation, f32 inexact literals: refused `kotoba.fe/unported`.
