# 型付きベクトル解析：既定OFFのネイティブ確認

解析専用のKotoba版V1を、既存のAmu製ネイティブコンパイラでソースから作成した。解析は無効のまま、4世代すべて918,120 B・オフセット0・SHA-256 `3893f7073bfee306f1f1d5502180b4187747f2fc2c38a58f0888121e2ea687e2`で一致した。元のEmbench19本もこのコンパイラで作り直し、全ソース・ネイティブ全体・exportオフセットが現在のcharged-compare実験版と一致した。これは新しい性能値や最適化適用数ではない。

入力は既定OFFのunity `aab2b95c9c6064fde2ca206a4ec736c92d4a67704aa477de4e84cda3c37abfb3`、起点はAmu製の `3ad29932428206a84a8c571a8089a793d0dcf95d167c23cbcbb43effdba2a346`。Node・nbb・JVMでビルドしていない。最初のローダー呼び出しはsandbox初期化拒否125でコンパイラに入る前に停止し、ログを保存した。ソースを変更せず、専用フォルダーでローダー自身のsandboxを使うための権限回復を別工程として登録した。後続の自己ビルド8件と19本のcompile/extract38件は成功。計47呼び出しを46成功＋1起動前拒否として扱い、ベンチマーク実行47件とは呼ばない。

型付きソースの独立レビューでは、有限範囲確認・非関数定義・成功したG確保の直後だけのhook・中断時の全候補破棄を構造的に確認した。厳密な作業量の定理、解析有効版のメモリ状態や生成規則の資格は未完了。既定OFFは入口から元のMを返し、解析の領域走査・書き込みに入らない。自己ビルド結果は生成・抽出の全8ログ、26バイトのKSEEDヘッダー、全payload、世代ごとの実際の入力とともに独立確認した。親担当は[3ファイル証拠](evidence/coscientist-inverse-aes-20261007/vector-typed-default/README.md)のみを別ディレクトリへコピーし、19本の実バイト比較も再検査した。

解析有効版V1の上限問題も保存した。1回の全状態消去は33,536×128=4,292,608作業単位で、他の処理を除いても最大62回。さらにラベル重複の逐次走査は、PicoJPEGの2,226ラベルで1,505,360,768、QRduinoの1,380ラベルで538,896,128となり、上限268,435,456を超える。これは実測時間ではなく、固定ソースと実際のSIRによる静的下限。解析有効版V1を走らせて肯定結果を得たとは主張しない。

実行前にV2の変更を登録した。関数ごとの初期化はcurrent512＋CFG256の768ワードに減らし、新しいblockの128fact×4fieldを上書きしてから読み取り可能にする。8193ワードのラベル表で重複を線形に検査し、CFG再利用前に消去する。作業上限268,435,456と終了時の全41,984ワード復元は維持する。V2は独立レビュー中で、今回の既定OFF確認から解析有効版の安全性・候補数を推論しない。
